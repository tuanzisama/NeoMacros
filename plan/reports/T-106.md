## 1.21.6 obf 节点接入

- **工具链分叉机制**（本次最关键的实证发现）：
  - loom 1.19.3 对**旧插件 id `net.fabricmc.fabric-loom`** 硬编码 `disableObfuscation=true`
    并 `finalizeValue()`（反编译 LoomGradleExtensionImpl 实证）——即强制无映射工具链，
    恰好是 26.x（官方名无混淆 jar）所需；
  - **现代插件 id `fabric-loom`** 则读根 gradle.properties 的
    `fabric.loom.disableObfuscation=false` → 分层 Mojang 映射 + modImplementation
    （fabric-api 1.x 产物仍是 intermediary 名，必须走 remap）；
  - 1.21.6 客户端 jar 实为**混淆 jar**（a.class 计数实证）——loom 对旧版本的自动判断不可信，
    一切以插件 id + 显式 flag 为准。
- 构建脚本分叉：stonecutter `buildscript()`——1.21.6 用 `product/build.gradle.kts`
  （现代 id），26.x 用 `product/unobf.gradle.kts`（旧 id）；共享逻辑抽到
  `product/node-common.gradle.kts`（apply-from 脚本无生成访问器，全部显式 API），
  per-node API 重写移入 `buildSrc/NeomacrosNode.kt`（JsMacros 同款 buildSrc 模式）。

## 跨版本双机制定界

- **replace 对**：stonecutter 对条件另一侧**自动反向应用**（StringSpecImpl 反编译 +
  "rendering"→"extractRenderStateing" 事故实证）——因此只有 `to` 拼写从不出现于共享源码的
  对才能安全声明。现役对：KEYBOARD/KEYSYM、gui.hud/gui、ClientCommands/ClientCommandManager、
  KeyMappingHelper/KeyBindingHelper、registerKeyMapping/registerKeyBinding、
  getIdentifier/getLocation、extractor.text/drawString、outline 参数形、
  getDefaultClockTime/getDayTime、dimension().identifier()/location()、
  Identifier/ResourceLocation（<1.21.11）。
- **//? 注释交换**（结构性差异；inactive 分支用 `/* */` 包裹保证 raw 可编译；
  被包裹分支内部 `*/` 必须转义为 `^/`）：Screen render/extractRenderState（三块屏幕）、
  ChatComponent addServerSystemMessage/addPlayerMessage vs addMessage（ChatDisplayMixin）、
  KeyMapping.Category record vs 字符串分类（FabricInputPort）、ChunkPos record 访问器 vs
  public 字段（三 mixin）、gizmos vs WorldRenderEvents+RenderType.lines（FabricDraw3DPort）、
  setScreenAndShow vs setScreen（三处打开入口）、ObjectSelectionList.Entry.extractContent vs
  render(GuiGraphics,7int,bool,float)。
- 边界教训：`//?}` 必须圈住且仅圈住目标分支（外层类闭括号曾被卷入导致 EOF）；
  swap 的裸 26.x 侧必须自带 `//? if >=1.21.11` 守卫；1.x 分支文本直接写旧拼写
  （不依赖替换对），避免双向污染。
