新菜单语义与槽位索引（沿 G-019 的「整屏菜单序」，`regionOf` 词汇不变）：

- **furnace**：0 input / 1 fuel / 2 output（`smeltedItem`、`fuel`、`output`）；输入格宽高恒 1，`input(x, z)` 无视坐标读槽 0。
- **anvil**：0 firstInput / 1 secondInput / 2 result；`itemName` 是重命名框文本（不是产出保证）。
- **enchanting**：0 item / 1 lapis；三档线索按选项序 0-2。
- **brewing**：0-2 potions / 3 ingredient / 4 fuel。
- **grindstone**：0 topInput / 1 bottomInput / 2 result。
- **smithing**：0 template / 1 base / 2 addition / 3 result（`leftInput`→`template`、`rightInput`→`base`）。
- **stonecutter**：0 input / 1 output；`recipes` 与 `selectRecipe(idx)` 共用同一可见序号空间。
- **beacon**：0 payment（`payment`）。

**缺席语义**：菜单 data 缺失一律 `undefined`（不抛）；列表面缺席回 `[]`；配方类查询（`isFuel`/`isSmeltable`/`isBrewablePotion`/`isValidIngredient`/`isValidRecipe`/`previewPotion`/`fuelValues`）不依赖菜单，只在「拿不到数据源」时回 `undefined`/`{}`。

## 偏离与回写（需需求方确认后回写 12/13 号与 docs 类页）

1. **`FurnaceInventory.getInput()` 更名 `getSmeltedItem()`（破坏性）**：G-019 遗留②要求本批把 `FurnaceInventory` 改挂 `RecipeInventory`（JsMacros 同构），但基线里 T-510 落的无参 `getInput()`（返回冶炼输入堆）与继承来的 `RecipeInventory.getInput()`（`ItemStack[][]` 输入格）**同名冲突**，二者只能留一个。处理：无参 `getInput()` → `getSmeltedItem()`（正是 JsMacros 对该成员的命名），`input` 属性让位给 2D 输入格（与 JsMacros `RecipeInventory.getInput()` 同形）；同时新增 `getInput(int, int)` 覆写恒读槽 0（否则 1×1 网格算术会错读到燃料槽）。全库无测试/脚本引用旧名（已 grep）。
2. **`EnchantInventory.getCosts()` 返回类型 `int[]` → `List<Integer>`**、**`getEnchantmentIds()` 用 `List<String>` 而非 `String[]`**：引擎 `HostAccess.NONE` 下 Java 数组会包成 `JavaObject`（无下标/`length`），脚本读 `inv.costs[0]` 恒 `undefined`；`Payloads.snapshot` 对 `List` 走 `ProxyArray` 才可读。`getCosts` 是既有成员（T-510），此处属连带修复；`getRequiredLevels`（A）依赖它，不修则 A 不成立。
3. **`getEnchantmentHelpers` 13 §4 原判 D → 本批改判 B**：JsMacros `EnchantmentHelper` 是其自有包装类，但数据形状 `{id, level}` 与 NeoMacros 既有 `EnchantmentData`（`ItemStack.enchantments` 在用）完全一致，判 D 会白白留缺口。落点命名取 13 §4 已拍板的 `enchantments*`（不用 JsMacros 的 `*Helper` 词汇）。**建议回写 13 §4。**
4. **`canCraft` 按 JsMacros 实现为 `hasInputItem()`**，而非 13 §4 的 `output !== undefined`（后者是近似）。**建议回写 13 §4。**
5. **`isBrewablePotion(ItemStack)` 保留栈参**，13 §4 写的是 `isBrewable(id)?`（与 JsMacros 实签名不符）。**建议回写 13 §4。**
6. **`getFuelValues()` 落 `fuelValues` 属性**，13 §4 写的 `fuelValue(stack)` 与该成员无参 `Map` 签名矛盾。**建议回写 13 §4。**
7. **`getName/setName` → `itemName`/`setItemName`、`getMaximumLevelCost` → `costLimit`、`simulateXp` → `xpEstimate()`、`getRemainingFuelTime/getTotalFuelTime` → `fuelTime/fuelTimeTotal`、`getRemainingSmeltingTime/getTotalSmeltingTime` → `smeltingTime/smeltingTimeTotal`**：均按 13 §4 原文落地（后者 pair 按「剩余/总计」顺序解读，见映射表 30-33 行）。
8. **`getSmeltedItem`/`itemName`/`enchantments`/`recipes` 等新名与 `FurnaceInventory` 改挂**需 12 §4.6 / 13 §4 与 `NeoMacros-Docs` 类页回写（docsx 禁改）。

## 遗留

1. **`RecipeInventory.getCraftableRecipes()` / `getRecipes(boolean)`（G-019 遗留①，2 个）**：仍需新 `Recipe` 句柄类型（id/output/ingredients/canCraft）+ 配方书 tab 访问器（`ClientRecipeBook` → `RecipeCollection`），且客户端无通用 `RecipeManager`（`Level.recipeAccess()` 只有 `propertySet`/`stonecutterRecipes`），属跨任务类型建设。按任务卡「Recipe 句柄类型建设若过大可继续遗留」口径**继续遗留**；建议物品面批次（G-027/027B）或配方书专项承接，届时本报告 2 行转 B。
2. **26.3 远程服务器的 `fuelValues`**：燃料值在 26.3 是数据驱动 `ContextIntProvider` 树，解析必须有 `ServerLevel`（`LootParams.Builder(ServerLevel)`）；远程客户端只能回 `{}`。集成服务器下已实现（`getSingleplayerServer()` + `LootContextParamSets.BLOCK` + 熔炉方块状态）。JsMacros 同场景退回其内置硬编码表，NeoMacros 不复制该表（如需对齐，可作为后续专项）。
3. **`getSmeltedItem`/`itemName`/`enchantments` 等更名与 `FurnaceInventory` 改挂的文档回写**：12/13 号与 `NeoMacros-Docs` 类页按禁令未动，见「偏离与回写」⑧。
4. **`selectPrimary/selectSecondary` 的能级搜索按 JsMacros 语义**（主效果只搜 `min(level, 2)` 层、副效果在能级≥3 时按 JsMacros 的原版特例处理），未按原版按钮矩阵重写；如需严格原版语义需另行拍板。
5. **`previewPotion` 无匹配时返回原药水**（JsMacros 语义），因此该成员永不 `undefined`——只有「配方数据不可得」才回 undefined；文档已在 javadoc 写明。
