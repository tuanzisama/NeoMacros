## 关键实现笔记（后续 agent 必读）

1. **deepFreeze 不得触碰 ProxyObject**：glue 的深冻结若读取代理成员会触发活属性 getter（多计数一次）且冻结代理无意义——`__neoInstall` 只下钻原型为 Object.prototype/null 的 plain 对象
2. **ProxyObject 的 keys 必须返回代理数组**：HostAccess.NONE 下宿主 Java 数组不可读（"allowArrayAccess is false"）——用 `ProxyArray`
3. **glue 的 `__neoMakeAsync` 包装传参形态**：`hostFn(jsArgsArray, resolve, reject)`——异步函数实现必须解包 `arguments[0]`，不要把 resolve/reject 当方法参数
4. `installBindings` 每 context 仅安装一次（`defineProperty configurable:false`——二次安装抛 "Cannot redefine property: neo"，符合设计：reload 走新 session）
5. 引擎的值转换表：String/boolean/int/long/double/float 原生映射、UUID 由 String 解析、其余 `asHostObject()` 直通（快照/Handle 类参数 T-101 扩展）

## 偏离与回写

- 设计偏离: 无推翻性偏离。一处具体化：绑定函数签名为**值中立**设计（core 定义 `ModuleBinding`/成员类型，引擎负责 Value↔Java 转换与 ProxyObject 渲染）——由 core→ports 单向依赖不变式推出（core 不得 import GraalJS），05 §5 的"同一中间模型"语义保持（doclet 侧模型 T-024 已验证一致性思路）
- 架构文档回写: 无需（05 §2/§4/§5 均与实现一致）

## 遗留

- 参数值转换表按需扩展（宿主对象参数如 Pos3d 的 guest 侧构造语法属 T-101 的 Handle/Snapshot 设计时定）
- `PermissionError` 的 guest 类型化（脚本侧 `instanceof PermissionError` 语义）归 T-100 信任门（当前为宿主异常跨界，e.message 可读）
- Registry 每 view 重建绑定树的成本（模型小则可忽略；T-031 reload 时可加 view 级缓存）
