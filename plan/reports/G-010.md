## 2. 成员逐条映射

### 2.1 `getRespawnPos` → `neo.world.respawnPos`（落地）

- JsMacros 语义（JsMacros-CE `FWorld.java` 实证）：`>1.21.8` 读 `world.getRespawnData().pos()`，否则读 `world.getSharedSpawnPos()`；无世界返回 null。读的是**世界记录的重生数据**，不是 `Player.getRespawnPosition()`（床/锚点个人查询）。
- 形态：无参状态查询 → 属性（12 号 §4.0 铁律：`getX()` → `x`）；返回 `core/api/types/BlockPos` 句柄；无世界 → Java `null` → 引擎出口转 `undefined`（`GraalJsEngine.asGuestValue` 缺席规则）。
- 端口：`WorldPort.respawnPos(): Optional<Pos3d>`（缺席 = empty）。
- 适配器双实现（`//?` 换支，已核生成源）：
  - `<1.21.9`（即 1.21.6 节点）：`level.getSharedSpawnPos()`
  - `>=1.21.9`（26.1.2 / 26.2 / 26.3）：`level.getRespawnData().pos()`
- javap 实证：1.21.6 `Level.getSharedSpawnPos(): BlockPos` 存在、无 `getRespawnData`；26.1.2/26.2/26.3 `ClientLevel.getRespawnData(): LevelData$RespawnData`（组件 `pos(): BlockPos`）存在、`Level` 无 `getSharedSpawnPos`。

### 2.2 `getSkyLight` + `getBlockLight` → `neo.world.lightAt(x,y,z)`（落地，2:1）

- 合并依据：**12 号 §4.4 已设计** `lightAt (pos): {sky, block}`（标注【新增·P2】，Mojang 依据 `Level.getBrightness(LightLayer, pos)`）；13 号 §5.1 同名行归宿 B 指向 `world.lightAt`。两个 gap 成员是同一概念的两个光照层，按“一个概念一个面”不重复造 `skyLight`/`blockLight` 两个方法。
- 形态：`lightAt(double,double,double)` → `ports/model/LightData(sky, block)` record（缺席 = `undefined`，各层 0-15；`sky` 不含昼夜/天气修正，javadoc/`@zh` 已写明）。
- 版本差异：**光照无换支需求（javap 反查结论）**——
  - 1.21.6：`getBrightness(LightLayer, BlockPos)` 声明于 `net.minecraft.world.level.BlockAndTintGetter`，`LevelReader extends BlockAndTintGetter`；
  - 26.3：同签名方法声明于 `net.minecraft.world.level.BlockAndLightGetter`（26.x 把该接口改名/移动），`LevelReader extends BlockAndLightGetter`；
  - 两节点 `LightLayer.SKY/BLOCK` 同包同名；调用点 `level.getBrightness(...)` 沿继承链解析，签名一致 → 同一源码字节在四节点全通（四节点 `compileJava` 实证），故未加 `//?`、未进 `NeomacrosNode.kt` 替换表。

### 2.3 `playSoundFile` → `neo.world.playSoundFile(path, volume): Promise<void>`（落地，边界确认）

- 与既有 `world.playSound` 的边界（任务卡要求的 triage）：
  - `playSound(soundId, x,y,z, volume, pitch)`：**游戏声音引擎内的注册声音事件**（`BuiltInRegistries.SOUND_EVENT` → `level.playLocalSound` / UI 通道），受游戏音量设置约束、可定位；
  - `playSoundFile(path, volume)`：**播放磁盘上的音频文件本身**（宿主 Java Sound `Clip`），不经游戏声音引擎、不受游戏音量/定位约束；
  - 形态不同（事件 id vs 文件路径、void vs 文件 IO），按“形态不同才做”判 **B 落地**，不是 D。
- 形态取舍：JsMacros 返回 `javax.sound.Clip`（可 stop）。NeoMacros 包装层不允许把宿主句柄直接交脚本，且本任务允许文件清单不含 `core/api/types/**`（新 guest 类需登记绑定注册表，超范围），故映射为 `Promise<void>`：**playback 启动即 resolve，文件不可读/无法解码/音频线不可用时 reject**；`Clip` 的 stop 能力不映射（能力缩减，登记为遗留 L1）。异步（文件 IO）返回 Promise 符合 12 号 §2.6“读同步、动作异步”。
- 路径基准：绝对路径原样、相对路径对**游戏目录**（`FabricLoader.getGameDir()`），与 12 号 §4.11 `fs` 的单一基准一致（JsMacros 原为宏夹，未沿用）。
- volume：`0..1` 线性映射到混音器主增益范围（JsMacros 原语义）；无 `MASTER_GAIN` 控制时忽略。
- 权限：未标 `@ApiPermission`。12 号 §4.19 权限目录中 `fs` 覆盖面写死为 `neo.fs` 全部，且播放路径只解码音频、脚本读不到文件内容，无越权读面；如需求方希望把“读磁盘”整体挂 `fs` 闸门，需要先扩 4.19 目录（遗留 L3）。

## 6. 偏离与回写

1. **`getRespawnPos` 落点 = world 面**：13 号 §5.1 该行写的是 `player.self.respawnPos`（Mojang 依据 `Player.getRespawnPosition()`），但 JsMacros 原实现读的是 `ClientLevel` 的重生数据/共享出生点（世界级），且 G-010 任务卡落点明确为 `WorldApi/WorldPort/FabricWorldPort`、PlayerApi 在禁改清单 → 按任务卡落 `neo.world.respawnPos`。**建议回写 13 号 §5.1 行**（docsx 本任务禁改，未动）。
2. **2:1 成员合并**：`getSkyLight`/`getBlockLight` 合并为 `lightAt`，与 12 号 §4.4、13 号 §5.1 已有设计一致，非新偏离。
3. **`@ApiSince("0.7.0")`**：全库当前最高 0.6.0，按 G-001 报告“下一版本建议 0.7.0、以合并时基线拍板”取 0.7.0。
4. **光照未做双实现换支**：任务卡预期“光照需 26.x/1.21.6 双实现”，javap 反查后确认两节点签名一致（见 §2.2），以四节点编译为证不做 `//?`——属“核对后确认无差异”，非漏做。
5. **`playSoundFile` 返回形态**：`Clip` → `Promise<void>`，无停止句柄；JSDoc/d.ts 侧待 NeoMacros-Docs 重生成时按新签名落。
