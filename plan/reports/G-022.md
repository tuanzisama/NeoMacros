## 3. D 类证据（4 签名）

**定案依据**：任务卡实施要点「Lerp 插值器/亮度覆盖按 13 §2.3 标 D」；13 号 §2.3（T-522 定案 2026-11-11）`DisplayEntityHelper` 行：`getLerpTargetX/Y/Z/Yaw/Pitch` `getLerpProgress` `getSkyBrightness` `getBlockBrightness` → D，理由「26.x 插值器为私有 `GenericInterpolator`」。G-022 与该清单的交集恰为 4 个（X/P progress/sky/block brightness 不在本任务 members 内）。

**javap 可达性复核（1.21.6 与 26.3 各一次，另抽 26.1.2/26.2）**——如实记录，供协调方复议：

- `Display$GenericInterpolator`（§2.3 引证）确实存在且为 Display **私有嵌套类**（26.3 jar 实证），变换插值族不可达；
- 但**位置/朝向**插值走另一套 `InterpolationHandler`：1.21.6/26.1.2/26.2 有 public `Display.getInterpolation()`（1.21.6 的 `position()/yRot()/xRot()` 在插值激活时返回 `interpolationData` 存储的目标值，字节码实证）；26.3 `Entity.getInterpolation()` 为 public final、`InterpolationHandler.target()` 返回 `PositionAndRotation`（position/yRot/xRot）——**四节点理论上均可读到插值目标**；
- 与 JsMacros `getLerpTargetX` 的精确语义（"interpolated at `getLerpProgress(delta)`"，含其自身的进度插值数学）跨两代 API 对齐成本高，且任务卡明令按 §2.3 标 D。

**结论**：本任务按指令落地为 D（不实现、不挖 accessor）；可达性与 §2.3 理由的出入登记 §8-L2，若协调方复议改判 B，落点已就绪（`DisplayEntity` + `collectSpeciesState` 各加一行 + 一处 `//?` 换支）。

### 4.2 命名与形态

- 无参状态属性化（`isInvisible()`→`invisible`、`getHeadPose()`→`headPose`、`getLineWidth()`→`lineWidth`）；Mojang 无 get/is 前缀的查询词保持方法（`showArms()`、`showBasePlate()`，沿 G-012 `canBeSeenAsEnemy()` 先例）；`has*` 查询保持方法（`hasShadow()` 等，沿既有 `hasLeftHorn/hasPumpkin` 先例）。
- Mojang 官方命名优先：`getHeadRotation`→`headPose`（vanilla `getHeadPose`）、`isVisible`→`invisible`（13 号 §3.2 目标）、`getBillboardMode`→既有 `billboard`。
- 读同步：20 个新成员全为 `@ApiReadOnly` 属性/查询，无写动作、无 Promise。
- 缺席 = `undefined`：端口 `LinkedHashMap` 允许 null 值，facade `instanceof` 不匹配即返回 `null` → 引擎出口转 `undefined`（单测 `armorStandPoseReadsBackUndefinedWithoutState` 覆盖）。

### 4.3 为什么没有新增 `@Accessor`

任务卡要求「需要的私有 getter 走 interface + `@Accessor` + `neomacros$`」。逐条 javap 反查后本面一个都不需要：

- vanilla 即 public：`ArmorStand.showArms/showBasePlate/getXxxPose/isInvisible`、`Panda.getMainGene/getHiddenGene`、`Panda.Gene.isRecessive`、`Display.getBoundingBoxForCulling`（1.21.6–26.2）/`getInterpolatedBoundingBox`（26.3）、`TextDisplay.getAlign`+`FLAG_*`、`Entity.isInvisible`——两代同形；
- 本仓库 loom 工具链已放宽（`public final`，与既有调用同一通路，非本任务引入的新通路）：`Display.getBillboardConstraints/getWidth/getHeight/getViewRange/getShadow*`、`TextDisplay.getLineWidth/getTextOpacity/getFlags/getBackgroundColor/getText`、`ItemDisplay.getItemStack/getItemTransform`、`BlockDisplay.getBlockState`。既有 T-522 代码已在用同一批（`billboard`/`text`/`item`/`block`），本批未扩大通路类型。

故 `neomacros.mixins.json` 与全部 mixin 文件零改动。

### 4.4 数据通路

`collectSpeciesState`（适配器、主线程）→ `speciesState(uuid)` 平面 map → facade `species*` 助手按 key 读取。新值类型：`Pos3d`（姿态）→ `poseOf` 转 `Pos3D`；`BoundingBoxData`（剔除盒）→ facade 转 `EntityApi.BoundingBox`；`BlockData`（方块状态）→ facade 转 `types.BlockState(id, props)`；其余标量直通。跨到脚本侧时 `Payloads.snapshot` 把 record 拍成 `{min,max}`/组件 map，`Pos3D`/`BlockState` 走 ScriptHandle 代理——e2e 实测形状见 §7.1。

### 5.1 唯一 `//?` 换支（FabricEntityPort，Display 剔除盒）

```java
//? if <26.3 {
/*
var cullingBox = display.getBoundingBoxForCulling();
*/
//?} else {
var cullingBox = display.getInterpolatedBoundingBox(1.0F);
//?}
```

语义：26.3 的 `getInterpolatedBoundingBox(p)` 返回「场字段 + (lerp(p, old, cur) − cur) 位移」，`p = 1.0F` 时位移为 0，即**当前 tick 末（当前坐标）下的剔除盒**——与 1.21.6–26.2 `getBoundingBoxForCulling()`（`setPos` 即刷新的场字段）同语义，对齐 JsMacros「at its current position」。

## 6. 偏离与回写

1. **`isVisible` → `isInvisible()`（取反落地）**：13 号 §3.2 映射目标为 `invisible*`；JsMacros `isVisible` = 「invisible flag 未设」，compat 桥 `!x`。`EntityApi.java` 本任务禁改，故成员暂挂 `ArmorStandEntity`；**回写建议**：后续实体基类泳道将 `invisible` 上提 `Entity` 基类（`setInvisible` 同批核对，G-012 已证 Entity 面现无此成员）。
2. **`getVisibilityBoundingBox` 命名**：13 号 §3.2 草拟 `boundingBox*`，因与 `Entity.boundingBox`（碰撞盒）冲突改用 JsMacros 原名 `visibilityBoundingBox`；返回 `BoundingBox{min,max}`（比 JsMacros 的 `Vec3D` 更完整，compat 可派生其尺寸/角点任一形态）。
3. **Panda recessive 落两个属性而非 `isRecessive(gene)` 谓词**：13 号 §3.2 为 `isRecessive(gene)?⚠`；两 no-arg 属性与 gap 两签名 1:1、脚本侧免传参。
4. **`getBillboardMode`/`getMainGeneName`/`getHiddenGeneName`/`isPlaying`/`isLyingOnBack`/`isScaredByThunderstorm`/`isIdle` 判 A**：均为既有 T-522 成员的等值/组合回桥，未重复造面（先例：13 号 §2.3 `isHoldingBlock` A 不设成员）。
5. **姿态类型 `Pos3D` 而非 `float[]`**：JsMacros 返回 `float[3]`；按 12 号 §2.2/§2.6（Pos 系不可变、JSON 安全、组件具名）选 `Pos3D`，分量 = vanilla `Rotations` 原序。
6. **`ports/EntityPort.java` 零改动**：任务卡落点列出该文件，但通用 `speciesState` 通道已满足，无新端口面（见 §4.1）。
7. **需回写 13 号 §2.3**：`GenericInterpolator 私有` 的 D 理由与 `InterpolationHandler` 实际可达性出入（§3/L2）；`Display.getVisibilityBoundingBox`/Panda 命名确认（§2.3/§2.5）。docsx 本任务禁改，留给协调方。
