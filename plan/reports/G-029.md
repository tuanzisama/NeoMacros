## 设计（任务卡红线：不逐个硬编码 110 个方法）

```
state.props            // 既有：完整属性表 Record<string,string>（T-513）
state.getProp(name)    // 新：任意属性名 → string|undefined（68 个兜底成员的读取面）
state.hasProp(name)    // 新：属性存在性
state.getPropRange(n)  // 新：数值属性 [min,max]|undefined（5 个区间成员的读取面）
state.facing/level/…   // 新：26 个高频便捷成员（31 个 JsMacros 成员直读）
```

- JsMacros `UniversalBlockStateHelper` 的本质是"对单个 Mojang 属性实例的类型化读取 + 缺属性 throw"；NeoMacros `BlockState` 是无属性对象的不可变 DATA，属性表就是通道。**99 签名全部是属性读取，无一需要端口新数据**——D = 0 的依据。
- JsMacros throw → NeoMacros **缺席 = undefined**（12 号病灶 #6 口径）。
- `getPropRange` 语义与 JsMacros `getPossibleValues()` 区间等价：某方块全部定义状态里该键的数值极值 = 属性对象的可能值域（`IntegerProperty` 恒全值域，枚举属性按状态枚举）。

## 版本差异表（javap 两节点：1.21.6 layered-named ↔ 26.3 mojmap）

对照方法：`BlockStateProperties` 与全部相关枚举的 `<clinit>` 字符串逐常量配对；JsMacros CE 源的 stonecutter 门为旁证。

| 项 | 1.21.6 | 26.3 | 对本任务的影响 |
| --- | --- | --- | --- |
| **99 成员涉及的属性字符串名** | `facing/axis/half/type/shape/east/north/south/west/…`（共 121 常量） | 同名（124 常量） | **零漂移**：全部 99 兜底键两节点一致，props 读取无需版本门 |
| 字段/类改名（序列化名不变） | `CHISELED_BOOKSHELF_SLOT_0..5_OCCUPIED`、`DRIPSTONE_THICKNESS`（类 `DripstoneThickness`） | `SLOT_0..5_OCCUPIED`、`SPELEOTHEM_THICKNESS`（类 `SpeleothemThickness`） | 序列化名 `slot_*_occupied`/`thickness` 不变；JsMacros 用 `//? if >1.21.8` / `//? if >=26.2` 门（UBSH L819/L1036），**NeoMacros 按字符串读 props，天然零门** |
| 26.x 新增属性 | — | `side_chain` `copper_golem_pose` `potent_sulfur_state` | 不在 99 内；`props` 面自动携带，无代码改动 |
| 值集漂移 | `NoteBlockInstrument` 27 值 | 31 值（+`trumpet` `trumpet_exposed` `trumpet_oxidized` `trumpet_weathered`） | `instrument` 便捷成员返回值集扩大，无需改码 |

## 偏离与回写

1. **命名偏离（任务卡成员名 → NeoMacros 名）**：0 参 `getX` 按绑定层规则（`GraalJsEngine.handleShape`）发布为属性 `x`——`getBlockFace`→`face`、`getDoubleBlockHalf`→`half`（与 `getBlockHalf` 同键共享）、`isWaterlogged`→`waterlogged` 等；带参 `getProp/hasProp/getPropRange` 保留全名。JsMacros 的 `DirectionHelper` 返回值（`getFacing` 族）在 NeoMacros 为方向名字符串，包装为 DirectionHelper 属 compat 壳职责。
2. **同键多义的处理**：`type`（slab/chest/piston）、`shape`（stair/rail）、`half`（stairs/double-block）、`east/north/south/west`（wall shape/wire connection）、`mode`、`facing`、`axis`、`level`、`distance`、`age`——JsMacros 靠**属性实例身份**区分，NeoMacros props 只有字符串键。对策：高频歧义键（`type`/`shape`）的便捷成员按**值词汇表**门控；低频歧义（wall vs wire、mode 族）走 props 兜底，值词汇天然互斥，由调用方/compat 按方块语境判定。
3. **既有缺陷修复（允许文件内顺手）**：`FabricWorldPort.stateProperties` 原用 `String.valueOf(state.getValue(property))`，对 6 个无 `toString` 覆盖的枚举产出**大写**值（`SINGLE/HARP/FLOOR/SAVE/NONE/CEILING`），与 12 号 §2.4 "vanilla 方块属性"（blockstate JSON 小写）及 JsMacros `getSerializedName()` 相悖，`BlockScanMatcher` 也只好自行 `toLowerCase` 兜底。改为 `Property.getName(value)`（`EnumProperty.getName` 直通 `getSerializedName`）；方向/半部等本就小写的枚举值不变，既有测试 grep 无大写值依赖。
4. **`getPropRange` 返回 `List<Integer>` 而非 `int[]`**：e2e 实测 `int[]` 经 `asGuestValue` 落入 `JavaObject` 不透明代理（`Array.isArray` = false、下标不可读），`List` 走既有 `ProxyArray` 通道（与 `tags` 同形）。
5. **区间通道成本**：`getPropRange` 每次调用经 `blockType(id)` 重建方块类型事实（含全部状态枚举）。该族 5 成员为低频只读（JsMacros 同为按需查属性对象），暂不加缓存；若真机脚本热路径需要，后置"端口 propRange 通道/结果缓存"。
6. **零越界**：`Block.java`、`ports/model/*`、mixin、`WorldPort`（未加新方法——区间复用 G-017 既有 `blockType` 默认方法）、`PlayerApi/EntityApi/ClientApi`、`core/event/def/**`、`plan/TASKS.md`、docsx **全部零改动**；共享文件 `BlockState.java` 仅本任务改动（§6.2 G-017/G-029 串行，G-017 已合基线）。
7. 注解：全部 29 个新成员 `@ApiSince("0.5.0")` + `@ApiMC("*")` + `@ApiLoader("*")` + `@ApiReadOnly`（`AnnotationCompletenessTest` 三元组门禁绿）；注释英文 + `@zh`（带参成员另附 `@zh-param`）。
