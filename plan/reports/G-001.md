## 0. 一眼看懂（TL;DR）

1. **架构定案：保留式场景图（retained scene graph）+ 引擎侧每帧重投。** 元素状态是 core 侧的不可变 spec（volatile 发布 / COW 容器），渲染线程每帧按 `(层 z, 元素 z, 插入序)` 排序后，用中立 `DrawContext2d` 原语重放。**不引入任何 per-frame guest 回调**（T-200 遗留④"guest 函数线程安全"由此消除）。
2. **端口几乎不动。** `RenderPort.addLayer(id, z, painter)` 现有签名即为最终契约（painter 是 Java 侧 core 实现，不是脚本函数），只补 `setLayerZ`。Fabric 侧从"每条文本一个 HudElement"改为**单个常驻 HudElement + 内部 z 排序**（26.3/1.21.6 同管线，实测 fabric-rendering-v1 1.21.6 线已带 `HudElementRegistry`）。
3. **旧成员一个不删（compat 冻结契约）。** `hud.addText/removeText`（Promise）与 `neo.render.drawBox/drawLine/clearLayer` 是 jsmacros-compat 现役桥接目标，本稿把它们改写成 layer 模型上的糖（隐式 `$legacy` 层），签名与异步性冻结。
4. **元素即 Builder。** 0.x 拍板④下取"一个概念一个类"：句柄 setter 全部 fluent（`el.setX(4)` 返回 `this`），不另建 `XxxBuilder` 类族——此项与 15 号 G-032B/G-034/G-034B 任务卡里的 `Builder` 范围类**有出入，需需求方拍板**。
5. **模块卸载自动 clear 落到 owner 命名空间。** 层键 = `<模块名>:<id>`（owner 经 `LoadTracker` 解析，与 `EventsApi.on` 同机制），模块卸载即回收——补齐 HudApi javadoc 已承诺、但现状实现缺失的语义；owner 缺失（`thread.runOnMain` 里创建）时落全局桶，行为与今天一致。

### 1.3 生命周期与 owner 机制（关键发现）

- `HudApi` 类 javadoc 写着 *"until removed or the module unloads"*，但全仓**没有任何模块卸载清理 HUD 的挂钩**（`LoadedModule.track/onRelease` 只被 `EventsApi`/`NetApi`/`StorageApi`/`ThreadApi`/`PerformanceApi` 与 manifest 事件订阅使用）——文档语义未实现。
- `core/api/bindgen/LoadTracker.current()` 在**模块 context loop 线程上长期有效**（`ModuleManager.load` 里 `LoadTracker.begin(module)` 后不 end，注释明确"event callbacks and async continuations run there long after loading"）——即脚本在 `startup`、`events.on(...)` 回调里创建层都能解析到 owner。这是"模块卸载自动 clear"唯一现成的机制，本稿复用它。

## 2. 架构决策

### 2.1 分层（沿 15 号 §2 竖切）

```text
core/api/HudApi.java                 @ApiModule("hud")   模块门面：hud.layer / 兼容糖
core/api/render/RenderApi.java       @ApiModule("render") 模块门面：render.layer / 兼容糖
core/api/render/HudLayer.java        层句柄（G-032）= 场景图的容器节点
core/api/render/HudScene.java        @ApiInternal 场景图核心：owner 键、元素表、排序、painter
core/api/render/components/*         Draw2DElement 基类 + 组件（G-032B/034/034B/034C）
        ↓ 只依赖 ports（中立）
ports/RenderPort.java                addLayer/removeLayer/setLayerZ/layerIds（+ textWidth 复用，见 §5.2）
ports/model/DrawContext2d.java       中立绘制原语（唯一被 adapter 实现的绘制接口）
        ↓
product/adapter/FabricRenderPort.java 单常驻 HudElement + (z,id) 排序重放（四节点）
product/adapter/FabricDraw3DPort.java 形状改为按 (z,id) 键控（G-033 落地，本稿只定契约）
        ↓
e2e/StubAdapter.StubRenderPort        记录 painter + 注入帧（E2E-A 图元断言）
```

**关键选择：core 持有场景图、painter 由 core 实现，adapter 只提供"原语级"绘制。**

备选方案（被否）与理由：

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 元素 spec 下发端口，adapter 存元素 | 端口要长出 put/remove element 一族 record；对齐/百分比等几何计算若在 core 就重复一份 | 否：端口面变宽、几何两处实现 |
| B. 每帧调脚本 painter（现状 `BiConsumer` 直通 guest） | 与 T-200 遗留④冲突（guest 线程封送未验证），脚本卡顿直接拖垮 HUD | 否 |
| **C. core 场景图 + core painter + 中立原语（本稿）** | 端口几乎零改动；几何/排序可 core 单测；版本差异全部收敛在 `DrawContext2d` 实现；无 guest 每帧回调 | **采纳** |

### 2.2 每帧重投语义（明确五条）

1. **写入即发布**：脚本任何线程改元素属性 → facade 归一（坐标/颜色/百分比）→ 构造不可变 `*Spec` → volatile 写入该元素的 cell；结构变更（add/remove/clear/z 改变）→ 更新结构代数计数（generation）。
2. **下一帧消费**：渲染线程（Fabric `HudElement.render` 回调，主线程）读取 cell 的最新 spec 重放；**帧粒度"即改即生效"**，同一帧内脚本的多次写入以最后一次发布为准（不保证帧内中间态）。
3. **排序只在脏时做**：(层 z, id) 排序在 adapter 侧、(元素 z, 插入 seq) 排序在 core 侧，均带 dirty 缓存；元素量数百级时每帧零分配（复用上次排好的快照数组）。
4. **视口感知**：`layer.width/height` 每次解析时读注入的 `Supplier<WindowData>`（guiScale/窗口变化 → 下一帧自动 reflow，百分比坐标重算）；文本度量复用既有 `ChatPort.textWidth`（`FabricChatPort` 已在非渲染线程读 `font.width`，有先例）。
5. **3D 侧的重投由引擎承担**：`traceLine/entityTraceLine` 每帧按 uuid 重解析（现状已实现的模式），26.x 由常驻 `Gizmo` 每帧重发、1.x 由 `WorldRenderEvents` 重发——脚本无感（与 12 号 §4.15 原话一致）。

> **不做的事**：不向脚本暴露"每帧渲染回调"。JsMacros 的 `RenderElement.render(GuiGraphics, mouseX, mouseY, delta)` 既带 raw MC 类型（违反"包装层签名零 raw"）又要求每帧进脚本（反模式），**判 D，不映射**（见 §4.6）。

### 2.3 线程模型

| 动作 | 线程 | 机制 |
|---|---|---|
| 元素/属性变更（upsert、setter、remove、clear） | 任意（脚本 context loop / `runOnMain`） | 只写 core 场景图（volatile/COW），**不触端口** |
| 层注册/注销/改 z（端口调用） | 主线程 | `CompletableFuture.runAsync(..., mainExecutor)`；`Minecraft::execute` 是单线程 FIFO，注册序即调用序 |
| 绘制 | 主线程（渲染回调） | 只读场景图 |
| 文本度量 / 视口读取 | 任意 | 既有先例（`ChatPort.textWidth`、`ClientPort.window`） |

端口侧幂等规则（必须写进 `RenderPort` javadoc）：`addLayer(同 id)` **可重入**——覆盖 painter 与 z，不产生重复 Fabric 注册（修掉现状 `FabricHudRegistry.addText` 每次 remove+add 层的抖动）。

## 3. 持久元素 / 图层模型

### 3.1 图层（HudLayer）生命周期

```text
hud.layer(id, {z?})
   ├─ owner = LoadTracker.current()            // 模块 context loop 线程上恒有值
   ├─ key  = owner != null ? ownerName + ":" + id : id      // §3.5 命名空间
   ├─ 已存在(key) → 返回既有句柄（幂等，不重复注册端口）
   └─ 不存在 → 建 HudScene 节点 → 调度 render().addLayer(key, z, scene::paint)（主线程）
之后：
   layer.text(...)/rect(...)/...   元素 upsert（同 id 覆盖，稳定插入序）
   layer.setZIndex(n)              → 调度 render().setLayerZ(key, n)
   layer.setVisible(false)         纯 core 标记，painter 跳过（不碰端口）
   layer.clear()                   清空元素，层保留
   hud.removeLayer(id)             → 调度 render().removeLayer(key)；句柄置 disposed
模块卸载（LoadedModule.release hooks）→ 自动 dispose 本模块全部层（§3.5）
```

- **状态与失效语义**（沿 12 §2.6 规则 4）：`layer.disposed` 属性永远可读；disposed 后其余读属性返回 `undefined`、调方法 `throw new Error('layer no longer valid')`。
- 层的 `width/height` = 当前视口缩放像素（注入 `WindowData`），窗口未就绪时为 `0`（e2e 注入固定 640×360 供断言）。

### 3.2 元素（Draw2DElement）生命周期

- **upsert 语义**：`layer.text('pos', 'hi', {...})` —— id 不存在则创建，存在且**同组件类型**则原地更新并返回同一句柄（插入序不变），存在但**类型不同**则替换（旧句柄 `disposed`，方法调用 throw）。兼容 12 §4.15 "同 id 更新，即改即生效"。
- **删除**：`layer.remove(id)`、`layer.clear()`、整层 dispose；元素句柄随后失效（属性 `undefined` / 方法 throw）。
- **无独立 Builder**：元素句柄的 setter 全部 fluent 返回 `this`（JsMacros `Draw2DElement.setX(...): Draw2DElement` 本来就是返回自身的签名，语义 1:1）；配置与写入是同一个对象、同一个时刻（"一个概念一个类"）。见 §11 拍板项②。
- 每个元素持有 `layer` 反向引用（= JsMacros `getDraw2D()`），`parent` 见 §3.4。

### 3.3 z-index（两级，稳定排序）

```text
绘制序 = 层 zIndex 升序  →  层内元素 zIndex 升序  →  插入序（同 z 稳定）
```

- 层 z：跨层（adapter 侧 `ConcurrentSkipListMap<(z, id), painter>`）；**默认 `0`**，与现状 `FabricHudRegistry` 传 `0` 一致；负数允许。
- 元素 z：层内（core 侧）；默认 `0`。
- **相对原版 HUD 的位置不变**：所有 NeoMacros 层仍是一个 `addLast` 元素（原版 HUD 之上）。"某层夹在原版 hotbar 与 chat 之间"是**非目标**（现状语义即 addLast，12 §4.15 也未承诺），列为后续可扩的 `anchor` 选项（§11 拍板⑧）。
- 同 `(层, 元素)` 的 z 变更只改排序键，不重置插入序、不重建元素。

### 3.4 parent / 对齐 / 坐标系

- **坐标系**：屏幕缩放像素（scaled GUI pixels，左上角原点）——与现状 `DrawContext2d` 完全一致；不做 framebuffer 像素。
- **v1 容器只有一层**：`element.parent` 恒为所在 `HudLayer`（`undefined` 仅在元素已失效时）；`parentWidth/parentHeight` = `layer.width/height`。
  - JsMacros 的嵌套语义拆两半：
    - `Draw2D.addDraw2D(childDraw2D, x, y, w, h, z)`（15/13 已定 **P3' nested Draw2D**）→ 不在本波，`layer.group(id, opts)` 预留形态（组元素拥有子元素、参与对齐），P3 立项再实现；
    - `setParent`（把元素挂到另一元素）→ **v1 不暴露**（D/延后，回写 13/15，见 §12）。
- **对齐（G-034C 的 `Alignable` 面）**：全部是"相对兄弟元素或相对父盒"的纯几何，core 内算，不进渲染回调：

```ts
type Align = 'left' | 'center' | 'right' | 'top' | 'middle' | 'bottom';

element.alignTo(other: Draw2DElement, opts?: { h?: Align; v?: Align; hOffset?: number; vOffset?: number }): this
element.align(opts?:        { h?: Align; v?: Align; hOffset?: number; vOffset?: number }): this  // 相对层（父盒）
element.moveTo(x, y): this        element.moveToX(x): this        element.moveToY(y): this
element.bounds: { x, y, width, height }   // 解析后的绝对盒（缩放/百分比求值后）
```

- **百分比坐标**：`x/y/width/height` 接受 `number | `${n}%``；`n%` 在每次绘制时按父盒求值（`parsePercentage` 折叠进参数归一，不暴露静态方法）。字符串百分比是**类型放宽**（12 §4.15 的 `{x, y}` 本来只画了数字），非破坏。
- G-034C 的 `getScaledWidth/Height/Left/Top/Right/Bottom`、`getParentWidth/Height` → 折叠为 `bounds` + `parent.width/parent.height`（10 个 getter 收敛为 1 属性 + 既有层属性，映射回写见 §12）。

### 3.5 归属（owner）与"模块卸载自动 clear"

- **层键 = `<模块名>:<公开 id>`**，owner 取 `LoadTracker.current()`（与 `EventsApi.on` 同机制，覆盖 `startup` 与全部事件回调）。
  - 效果 a：两个脚本都写 `hud.layer('coords')` **互不干扰**（模块级隔离）；
  - 效果 b：`hud.layers` / `layer.ids` 只列**本模块**的层与元素 id（公开 id）；
  - 效果 c：模块卸载时 `LoadedModule.onRelease` 逐层 `removeLayer` + `dispose` → 落实 HudApi javadoc 与 12 §4.15 "模块卸载自动 clear"（**现状实现缺失，本稿补齐 = 行为变更，见 §11 拍板③**）。
- **owner 缺失**（在 `thread.runOnMain(...)` 里创建层、或单测直接 new facade）→ 键 = 裸 `id`，**无自动回收**（与今天行为一致）；文档明示"在 runOnMain 里创建的层请自行 clear"。
- 兼容糖 `hud.addText` 走隐式层 `$legacy`（owner 命名空间内），因此 compat 脚本卸载后其 HUD 文本一并消失——与 javadoc 一致；`$` 前缀保留给内部，用户 id 以 `$` 开头直接 throw。
- **3D 侧同样规则**：`render.layer(id)` 与 `neo.render.drawBox(layerId,…)` 的 legacy 层键同为 `<owner>:<id>`；owner 缺失时裸 id（`RenderApiTest`/现有脚本语义不变）。

### 3.6 每帧重放（painter 伪码，core 内部）

```java
// core/api/render/HudScene.java —— 非脚本可见（@ApiInternal）
void paint(int tick, DrawContext2d ctx) {
    HudSnapshot snap = snapshot();               // 缓存，结构代数变化时重建
    for (ElementCell cell : snap.ordered()) {
        ElementSpec spec = cell.spec();          // volatile 读
        if (!spec.visible()) continue;
        ResolvedBox box = spec.resolve(snap.viewport(), ctx);   // 百分比 / scale / align
        if (spec.rotation() != 0 || spec.scale() != 1) {
            ctx.transform(pivotX(box, spec), pivotY(box, spec),
                          spec.rotation(), spec.scale(), spec.scale(),
                          () -> spec.emit(ctx, box));
        } else {
            spec.emit(ctx, box);
        }
    }
}
```

## 5. 端口契约

### 5.1 `RenderPort`（中立，`ports/RenderPort.java`）

```java
public interface RenderPort {

    /**
     * Registers (or re-registers) a HUD layer at the given z-order. Layers
     * render after the vanilla HUD; higher z renders on top. Re-registering
     * the same id replaces its painter and z without creating a second
     * backing element. The painter is a host-side (core) callback invoked on
     * the game main thread once per frame with a tick count and a neutral
     * draw context; it is never a script function.
     */
    void addLayer(String id, int z, BiConsumer<Integer, DrawContext2d> painter);

    /** Removes a previously registered layer; unknown ids are ignored. */
    void removeLayer(String id);

    /** Changes a registered layer's z-order without re-registering it. */
    void setLayerZ(String id, int z);            // ← 本稿唯一新增方法

    /** Returns all registered layer identifiers in render order. */
    Supplier<List<String>> layerIds();
}
```

- 层 id 对端口是**不透明字符串**（含 owner 前缀），端口不做名称合法性校验。
- 全部调用约定在主线程（facade 负责跳变）；实现侧数据结构须并发安全（脚本线程改 z 与主线程渲染可能重叠，`setLayerZ` 允许任意线程调用亦可，实现用并发 map 即可——在 javadoc 写明"实现必须并发安全"）。
- **中立 record（`ports/model/`）本稿不新增**：元素 spec 属 core 内部（不跨端口），跨端口的只有 `DrawContext2d` 原语与既有 `WindowData`/`ItemStackData`/`ImageData`。这是"端口只加中立方法/record"的最窄解。

### 5.5 `FabricRenderPort`（26.3/1.21.6 HudElementRegistry 管线改造）

```text
现状：每层一个 Fabric HudElement（addLast），z 被忽略；addText 每次 remove+add 层。
改后：单个常驻 Fabric HudElement，标识符 `neomacros:hud`（固定，与脚本 id 解耦）：
  - 首次 addLayer → 主线程 HudElementRegistry.addLast(neomacros:hud, element)

  - 层 id 不再参与 Identifier 拼接 → 彻底规避 owner 前缀/模块名的字符合法性问题
收益：①z 真正生效（层间顺序确定）；②无注册表抖动；③跨 mod 位置语义与现状 100% 相同（仍 addLast）。
```

`DrawContext2d` 匿名实现仍内联在该类（现状惯例），替换表字面约束见 §6。
