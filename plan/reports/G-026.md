## 命名与形态决策

1. **kind 命名沿 Mojang/既有词表**：`long` `uuid` `identifier` `time` `literal`——与既有 `int/float/bool/word/string/greedy/player/pos` 同族，JsMacros 的 `*Arg`/`*ArgType` 词缀一律不沿用（13 号 §1 规则 5）。
2. **`range(min, max)` 是链式方法而不是工厂重载**：与既有 `optional()`/`default(v)` 同一形态（`CommandArg` 不可变，返回新槽位）；`Number` 形参避免 `long/double` 双重载在 `JavaInteropResolver.dispatch` 的同名歧义（G-024B 已记录 handleShape 同名重载坑）。仅 `int/long/float` 可挂，倒置边界与非数值槽直接抛错。
3. **`literal()` 默认词 = 槽键**：compat 映射 `literalArg("set")` → `{set: arg.literal()}` 最短；需要键名与词分离时 `arg.literal('show')` 显式指定（工厂实参透传，本批打通 `CommandArgFactory.readCallable/invoke` → `CommandArg.of(name, args)`）。
4. **`uuid()` 交付字符串而非 `java.util.UUID`**：沿 `Payloads.snapshot` 既有中性化规则（UUID → 字符串），宿主单测与脚本看到同一形态，避免「宿主 UUID / 脚本 string」两副面孔。
5. **`string()` 引号升级不破坏旧语义**：未加引号的 token 行为逐字不变；`word()` 显式拒绝带引号 token，两者从此分化（此前完全同义）。
6. **greedy 交原始切片**：分词器记录 token 偏移，`greedy()` 用 `remainder.substring(start)` 交还原文（保留内部连续空格与引号），不再重拼 token 列表。

## 与 JsMacros 的语义差异（有据）

1. **`uuidArgType` 值形态**：JsMacros 交付 `java.util.UUID`；NeoMacros 交付规范化小写文本（见上 4）。
2. **`intRangeArg`/`floatRangeArg`**：JsMacros 交付 brigadier range 对象；NeoMacros 判 D，闭区间用 `range(min, max)` 表达。
3. **`itemSlotArg`**：JsMacros 交付 int 槽索引；NeoMacros `word()` 交付槽名/槽号原文（`hotbar.0` → 索引换算在脚本侧）。
4. **`blockPosArg`/`columnPosArg`**：JsMacros 交付按命令源解析的 `BlockPosHelper`（含 `~`/`^`）；NeoMacros `pos()` 交付原始 token，解析在脚本侧（与既有 `pos()` 槽现状一致）。
5. **`timeArg` 单位**：沿 JsMacros/brigadier「单位必填」（`t`/`s`/`d` → 1/20/24000 ticks），裸数字与未知单位拒绝。
6. **`literal()` 的回读值**：JsMacros 的 literal「无值可读」；NeoMacros 把命中的固定词写进 `ctx.args[key]`（无害且便于断言）。
7. **类型解析失败的呈现**：沿既有语义从 `executes` 抛 `IllegalArgumentException`（本批未改，见遗留 7）。

- 为什么必须改：该分支是「对象字面量里的 JS 函数」唯一入口（`command.register({handler})` 走的就是它）。`HostAccess.NONE` 下 `context.asValue(宿主对象)` 交给脚本的是**不可读的宿主对象**——实测修复前 e2e 报 `TypeError: Cannot read property 'verb' of undefined`（`ctx` 存在、`ctx.args` 恒 `undefined`），即 **typed DSL 的 handler 从脚本侧从来读不到 `ctx.args`**（此前无任何脚本级测试覆盖命令模块，故未暴露）。
- 为什么这样改：与同文件 `adaptFunction`（直接函数形参路径）已经使用的 `guestValueOrEvent` 对齐——句柄渲染成 guest 类、容器渲染成 proxy、标量逐字不变；`null` 由 `null` 变 `undefined`，恰符合 ES 面「缺席 = undefined，永不出 null」的既定规则。属「把 opaque 变 readable」的单向改善，不改变任何已可读值的形态。
- 影响面：所有「嵌套在容器里的 JS 回调」（全仓目前仅 `command.register` 的 handler 一处）；`./gradlew :engine:test` 51 例、`:e2e:test` 52 例、`./gradlew build` 全绿。
- 协调口径：G-026B 及其他泳道如需动同一行/同文件，按 15 号 §6.2 先串行；本行已写注释说明动机，勿回退。
