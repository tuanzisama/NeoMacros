### D 证据

- **§D1 `EventLaunchGame.playerName` → D**：JsMacros 取 `mc.getUser().getName()`（`MixinMinecraftClient` 构造 `EventLaunchGame(this.user.getName())`，会话账号名）。NeoMacros 侧三重拿不到：① `game:start` 于进世界前触发，`player.self` 缺席（13 §6.2 该行原标 `playerName*（player.self.name 可推，核对后定）`——**核对结论：推不出**）；② `ClientPort` 无会话名/用户面；③ `GameStartEvent` 在 `def/lifecycle`（任务卡落点外）。等价配方（穿透层）：`java.type('net.minecraft.client.Minecraft').getInstance().getUser().getName()`。
- **§D2 `EventMouseScroll.deltaX` → D**：`MouseScrollMixin` 入参有 `xOffset` 但只转发 Y 轴（`InputScrollHub.fire(yOffset)`），`InputPort.onScroll(Consumer<Double>)` 为单轴签名；补水平轴需改 `ports/InputPort` + `InputScrollHub` + `MouseScrollMixin` + `FabricInputPort`（均在本任务落点外）。等价面：无（常规鼠标水平滚动恒 0；脚本可自行约定 0）。
- **§D3 `EventRecvMessage.signature` → D**：NeoMacros `chat:receive` 源为**显示路径**——`ChatDisplayMixin.addPlayerMessage(message, signature, tag)` 入参虽有 `MessageSignature`，但 `ChatReceiveHub.fire(ChatComponent.plain(...))` 只转发纯文本组件；扩签名需改 product 侧 hub + `ChatPort`（ports 根，落点外）。且 `byte[]` 签名是聊天上报链的机器签名（JsMacros 原样透传、无判读面），非脚本可消费值。等价面：无。
- **§D4 `EventRecvMessage.messageType` → D**：JsMacros `messageType = GuiMessageTag.logTag()`（"Chat Error"/"Command" 等 HUD 标签）。同 §D3：tag 在 mixin 入参处存在、hub/端口不携带（落点外）；pre-26 分支 `addMessage` 单入口连 system/player 文本都无法区分（`ChatDisplayMixin` javadoc 原文）。等价面：无。
- **§D5 `EventBlockUpdate.block` → D**：JsMacros 为 `BlockDataHelper` **活句柄**（含 `getBlockState/getNBT` 等），冻结载荷禁活句柄（12 §5.1 / `@ApiEvent` "never live game references"，G-013 同口径）。等价面：载荷既有 `pos` + `id`，完整方块数据经 `world.blockAt(x, y, z)`（`WorldApi` 已有）。
- **§D6 `EventBossbar.bossBar` → D**：JsMacros 为 `BossBarHelper` 活句柄（`LerpingBossEvent`），同 §D5 禁入载荷。等价面：载荷既有 `uuid` 标识 + `world.bossBars()`（`WorldApi` 已有，`BossbarHub` 快照 `BossBarSnapshot{uuid,name,progress,color}`），按 uuid 关联。
- **§D7 `EventBossbar.type` → D**：`type` 是 BaseEvent 保留 payload 键（`EventDescriptor.RESERVED_PAYLOAD_KEYS = {type, timestamp, cancellable, direction}`，同名组件在 `EventDescriptor.from` 抛出；G-013 `EventSlotUpdate.type` 先例即此判 D）。等价面：既有 `action`——JsMacros 值域 `ADD/REMOVE/UPDATE_PERCENT/UPDATE_NAME/UPDATE_STYLE`（`BossBarConsumer`）与 NeoMacros `add/remove/updateProgress/updateName/updateStyle` 一一对应（大小写/词形差异由兼容壳映射）。
- **§D8 `EventDisconnect.message` → D**：JsMacros 取断开屏 reason（`MixinMinecraftClient`：`((MixinDisconnectedScreen) nextScreen).getInfo().reason()`）。NeoMacros `world:leave` 由 `LifecyclePort.onWorldLeave(Runnable)` 发布——端口无 reason 参数、`WorldLeaveEvent` 无载荷；扩端口需改 `ports/LifecyclePort` + fabric/stub 实现 + `def/lifecycle` 记录（均落点外）。13 §6.2 `world:leave/reason` 本就标 ⚠ 待 T-519，本行并入该待办。
- **§D9 `EventJoinServer.player` → D**：JsMacros 为 `ClientPlayerEntityHelper<LocalPlayer>` 活句柄，同 §D5 禁入冻结载荷。等价面：`player.self`（进世界后本地玩家活句柄；`world:join` 载荷另有 `address`，与 JsMacros 同事件的 `address` 字段同义）。
- **§D10 `EventPlayerLeave.player` → D**：JsMacros 为 `PlayerListEntryHelper` 活句柄，同 §D5 禁入载荷；载荷已带条目标识 `uuid` + `name`（超集部分）。条目其余字段（latency/gamemode/displayName）离开后无法从 `world.tabList()` 回读（该面只含在场条目），发布点快照需改 `player:leave` 记录——player 域本任务禁改。
