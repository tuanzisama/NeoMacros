## 判定口径（本任务为什么是 0 B）

- 任务实施要点原文：「能映射到 input.movement/pressedKeys 的补，其余 D」。
- 类级归宿（`gap/mapping.json`，manual）：`PlayerInput → MovementSpec`（已存在，`InputApi.MovementSpec`）；`KeyTracker → module input`（notes：「按键跟踪状态；input.pressedKeys 覆盖」）。
- **可映射面已由前波落地，无需新增脚本面**：写 = `input.movement({forward,…})`（T-424），读 = `input.movementState`（T-504），按键态 = `input.press/release` + `input.pressedKeys`（T-424）。12 员里能映射的 7 员全部由这些既有成员承载（A = 桥接现有面，去重不重建，同 G-028 #28 口径），因此 B = 0 是判定结果而非缩水。
- **D 先例查证**（任务卡要求）：
  - 13 号 §5.2 行：`createPlayerInput / createPlayerInputsFromCsv/Json / addInput(s) / clearInputs / getCurrentPlayerInput / move*` → B 到 `input.movement` + `input.movementState`，并明文「**CSV/JSON 构造由脚本侧自行组装**」——即 `PlayerInput.fromCsv/fromJson` 不建解析面。
  - 15 号 §5.1 D 表：FPlayer 16 员（含 `createPlayerInputsFromCsv/Json`）已判 D；`gap.json` 同批成员 compatReason = "NeoMacros exposes no movement input synthesis"。该判定覆盖本任务 `fromCsv/fromJson` 的同一构造能力（本任务成员是其数据类对偶）。
  - `getCurrentPlayerInput` 在 gap.json 判 "no movement input introspection"——`yaw/pitch` 字段随该内省面一并 D。
