## 2. 总形态与入口

### 2.1 声明式单步入口（推荐）

```js
const gui = player.buildScreen({
  title: 'Shop',                 // 必填，纯文本
  showTitle: true,               // drawTitle 字段 → 默认 true
  pause: false,                  // isPauseScreen/shouldPause 字段 → 默认 false
  closeOnEsc: true,              // shouldCloseOnEsc 字段/方法 → 默认 true
  returnTo: 'current',           // setParent → 'current' | 'game'，缺省捕获开屏前的屏
  controls: [
    { type: 'button',    id: 'buy', x: 10, y: 40, width: 98, height: 20,
      label: 'Buy', onClick: (e) => neo.chat.log('bought ' + e.id) },
    { type: 'checkbox',  id: 'dbg', x: 10, y: 70, width: 98, height: 20,
      label: 'Debug', checked: true, onChange: (e) => { /* e.checked */ } },
    { type: 'slider',    id: 'amt', x: 10, y:100, width: 98, height: 20,
      value: 0.5, steps: 10, onChange: (e) => { /* e.value 0..1 */ } },
    { type: 'editBox',   id: 'name', x:10, y:130, width: 98, height: 20,
      maxLength: 32, onChange: (e) => { /* e.value */ } },
    { type: 'cycleButton', id: 'mode', x:10, y:160, width: 98, height: 20,
      values: ['A', 'B', 'C'], initial: 'A', onChange: (e) => { /* e.value */ } },
    { type: 'lockButton',  id: 'lock', x:10, y:190 },
    { type: 'imageButton', id: 'icon', x:10, y:220, width: 20, height: 20,
      sprites: { enabled: 'gui/buttons', disabled: 'gui/buttons',
                 enabledFocused: 'gui/buttons', disabledFocused: 'gui/buttons' } },
  ],
  // 屏级回调（setOn* 六个 + setOnRender，字段即注册）
  onMouseDown: (e) => false,      // e = {pos: Pos2D, button, modifiers: string[]}
  onMouseDrag: (e) => false,      // e = {pos, delta: {x,y}, button, modifiers}
  onMouseUp:   (e) => false,
  onKeyPress:  (e) => false,      // e = {key: 'key.keyboard.r', code, modifiers}
  onCharTyped: (e) => false,      // e = {char: 'r'}
  onRender:    (e) => {},         // e = {ctx: ScreenCanvas, mouse: {x,y}, partialTick}
  onClose:     () => {},          // 每会话恰好一次（任意关闭路径）
});

// ---- 会话句柄（写面）----
gui.controls;                     // ControlState[] 快照（getButtonWidgets/getTextFields）
gui.control('buy');               // ControlState | undefined
gui.add({ type: 'button', id: 'more', x: 10, y:250, width: 98, height: 20, label: 'More' });
gui.setControl('dbg', { checked: false });   // 通用状态写（G-035 基底）
gui.remove('more');
gui.on('mouseDown', (e) => true); // 运行期换回调（setOn* 6 个的动态版；name 白名单）
gui.shiftDown; gui.ctrlDown; gui.altDown;    // isShiftDown/isCtrlDown/isAltDown
gui.name; gui.title; gui.closed;  // getScreenClassName / getTitleText / 会话失效自检
gui.reload();                     // reloadScreen：按 spec 重建控件（保留 live 状态）
gui.close();                      // 关闭意图：onClose → 回父屏
```

要点：

1. **单步 build = JsMacros `Hud.createScreen` + `openScreen` 两步的合一**（13 号 §5.5 已定归宿 `screen.build`）。compat 桥接：`createScreen` 在 JS 侧本地累积 spec，`openScreen` 时一次性调 `buildScreen`；开屏后 `addButton` 走 `gui.add`。
2. 控件 = **冻结数据对象**（`ControlSpec`），非活对象；活状态读经 `gui.control(s)` 快照，活写经 `gui.setControl` / G-036 起的类型化句柄。
3. 回调一律**单参冻结事件对象**（浏览器风格），与 `CommandSpec.handler` 同一套解包机制。

## 3. ScreenSpec / 控件 API

### 3.1 类清单（`core/api/render/screen/`，G-035 建包）

| 类 | kind | 说明 |
| --- | --- | --- |
| `ScreenSpec` | DATA record | 建屏配置：`title` + 可选 `showTitle/pause/closeOnEsc/returnTo/controls` + 7 个 `on*` 回调字段（`@ApiType` 函数型，同 `CommandSpec.handler`） |
| `ControlSpec` | DATA record | 单判别式 record（`DialogConfig` 惯例）：`type, id, x, y, width, height` + 可选 `z, label, checked, value, steps, text, maxLength, suggestion, editable, values, initial, alternatives, prefix, locked, active, visible, showMessage, sprites{4}, onClick, onChange`；`type ∈ button/imageButton/checkbox/slider/editBox/cycleButton/lockButton` |
| `ControlState` | DATA record | 控件活状态只读快照：`id, type, x, y, width, height, z, label, active, visible, checked?, value?, text?, locked?`（缺席=undefined） |
| `BuiltScreen` | HANDLE | 会话句柄（§4） |
| `ScreenCanvas` | HANDLE | `onRender` 内的**短命**绘图上下文（§8.2）；回调外使用即 throw |

- 单 `ControlSpec` 而非分型族：与 `DialogConfig/CommandSpec/配置袋` 惯例一致，d.ts 单 interface 即可；分型 union 为可选拍板项（§13-6）。
- 校验在 facade：未知 `type` / 缺 `id` / 重复 `id` / `type` 与字段不匹配（如 button 带 `values`）→ 同步 throw（`IllegalArgumentException` → JS Error）；`title` 缺省空串允许。
- 回调字段**不进端口**：facade 解出后存进会话，端口只见中立数据 + `SessionSink`（§9）。

### 3.2 控件树 / 布局

- 树 = `ScreenSpec.controls` **有序列表**（无嵌套容器，v1 平铺；G-036B 之后若需容器另立提案）。
- 布局 = 绝对坐标（`x/y/width/height`，缩放坐标系 = MC scaled GUI 坐标，与 vanilla 控件一致）。
- **z 语义**：可选 `z`（默认 0）仅决定**同屏内控件的绘制/命中的排序**——构建时按 `(z, 声明序)` 稳定排序后 `addRenderableWidget`；MC 无逐控件 z，文档写明"z 只排序不叠加到 HUD"。JsMacros `addButton(..., zIndex, ...)` 的 zIndex 参数即此字段。
- 重建规则（resize / `reload()` / `add` / `remove`）：**先把 live 控件状态回写 spec（`adoptLiveState`：text/value/checked/locked），再整体重建**——保证窗口缩放与动态加控件不丢输入；`add/remove` 采用整树重建（小 GUI O(n)，顺序唯一、行为可测），不走增量挂载。
- 状态真源：**spec = 构建描述的真源；widget 实例 = 运行期真源**；脚本写（`setControl`/类型化句柄）同步落到 widget + spec 镜像；键入/拖动等控件内变化由 `stateChanged` sink 回写缓存（spec 镜像在下一次 adopt 时刷新）。

### 3.3 控件类型 → vanilla 控件（adapter 侧构造表）

| `type` | vanilla 类（四节点齐备，javap 实证） | 关键映射 |
| --- | --- | --- |
| `button` | `Button.builder(Component, OnPress).bounds(x,y,w,h)` | `label`→message，`onClick`→OnPress |
| `imageButton` | `ImageButton(int,int,int,int, WidgetSprites(4), OnPress)` | `sprites.{enabled,disabled,enabledFocused,disabledFocused}` ↔ WidgetSprites 四元组（与 JsMacros TexturedButtonBuilder 四个 texture 一一对应） |
| `checkbox` | `Checkbox.builder(Component, Font).pos(x,y).selected(b).onValueChange(...)` | `checked`↔selected；`showMessage` 透传（语义待 compat 实测） |
| `slider` | 自建 `AbstractSliderButton` 子类 | `value`（0..1）+ `steps`（>0 时离散吸附）；onDrag/onValueChange→`onChange` |
| `editBox` | `EditBox(Font, x, y, w, h, Component)` | `setResponder`→`onChange`（每键入）；`maxLength/suggestion/editable` 直映 |
| `cycleButton` | `CycleButton.builder(valueToText, initial).withValues(list[,alternatives])` | JsMacros `alternatives`↔`withValues(List,List)`；`alternateToggle`↔`withValues(BooleanSupplier, List, List)`（vanilla `DEFAULT_ALT_LIST_SELECTOR` 同源） |
| `lockButton` | `LockIconButton(x, y, OnPress)` | `isLocked/setLocked` 原生对应；adapter 在 onPress 翻转 locked 并发 click/change |

> JsMacros 的 `XxxWidgetHelper` 命名不沿用（15 号 §1.3）；guest 类名一律 Mojang 原词（§5.2 表）。

## 4. BuiltScreen 会话句柄（G-035 guest 面）

```java
@ApiClass(name = "BuiltScreen", kind = HANDLE, wraps = "net.minecraft.client.gui.screens.Screen")
public final class BuiltScreen implements ScriptHandle { … }
```

| 成员 | 类型 | 说明 / 对应 JsMacros |
| --- | --- | --- |
| `title` / `name` / `closed` | 只读属性 | `getTitleText`（纯文本，富文本标题=缩水）/ `getScreenClassName`（宿主类名 `ScriptScreen`）/ 会话自检 |
| `shiftDown` `ctrlDown` `altDown` | 只读属性 | `isShiftDown/isCtrlDown/isAltDown`（§8.3 差异实证） |
| `controls` | `ControlState[]` | `getButtonWidgets`/`getTextFields`（compat 按 `type` 过滤） |
| `control(id)` | `ControlState \| undefined` | 单控件快照 |
| `add(control)` | `BuiltScreen` 链式 | **18 个 `add*` 签名的唯一原生载体**（§5.1） |
| `remove(id)` | `BuiltScreen` | 动态删控件 |
| `setControl(id, patch)` | `BuiltScreen` | 通用状态写（checked/value/text/locked/label/active/visible/z）；G-036 类型化句柄是其糖 |
| `on(name, fn)` | `BuiltScreen` 链式 | 运行期换回调；`name ∈ {mouseDown, mouseDrag, mouseUp, keyPress, charTyped, render, close}`（`setOn*` 6 个 + `setOnRender` + `setOnClose` 的动态版） |
| `close()` | void 同步 | 关闭意图；已关闭 → throw（§2.6 规则4） |
| `reload()` | `BuiltScreen` | `reloadScreen`：adopt 后按 spec 重建，**同会话不失活**（回调/owner 保留） |
| `returnTo` | 只读属性 `'current'\|'game'` | `setParent`：开屏时自动捕获前屏；**开屏后不可改 = 缩水标注**（compat 把 setParent 映射到 spec 字段，开屏后调用记缩水） |
| `widget/button/checkbox/slider/editBox(id)` | G-036 | 类型化活句柄（§5.2） |
| `widget(id)` | G-036B | 统一基类句柄 |

不变量：

- 句柄**失效规则**（§2.6 规则4）：`closed=true` 后所有变更方法同步 throw，属性读回 `closed/title/name`；`controls` 返回 `[]`。
- 一个会话 = 一次 `buildScreen`；任何屏替换路径（被别的脚本/vanilla 屏覆盖、断线、owner 卸载）都会把会话推到 `closed`，**`close` 回调恰好一次**（幂等闸）。
- **owner 与卸载**：`buildScreen` 记 `LoadTracker.current()`；`LoadedModule.close()` 经一条新增 disposer 跟踪关闭会话（复用其 auto-dispose 通道，G-035 给 `LoadedModule` 加一项通用 `track(Runnable)`）。owner 为空（罕见路径）时回调派发以 context 存活为前提，异常吞掉 + 限流日志。

## 6. 生命周期与关闭语义

### 6.1 状态机

```text
buildScreen(spec)
   │  主线程跳 open（MainThread.run；失败/超时 → 同步 throw，e2e 可 catch）
   ▼
 open（displayed）─── 任意路径关闭 ───▶ closed（终态）
   │  ① Esc/closeOnEsc → onClose()      （onClose 回调恰好一次）
   │  ② gui.close() → 同 ①
   │  ③ 被其他屏替换（vanilla/他脚本）→ removed()：**不回父屏**，仍发关闭通知
   │  ④ 断线 / owner 卸载 → 主线程关屏，回父屏
   ▼
 关闭意图（①②④）：onClose 回调 → returnTo='current' 恢复捕获的父屏，否则 setScreen(null)
```

- **回调与失效顺序**：`close` 回调先于句柄置 `closed`（回调内仍可读 `gui.title/controls`，但再 `add/close` → throw，防重入）。
- 父屏捕获：`open` 时记 `currentScreen()`（与 `FabricDialogPort.show` 同款）；若捕获到的恰是上一个未关闭的脚本会话，先触发其关闭通知再开新会话（单屏不变量）。
- `screen:open/close/change` 事件由既有 per-tick 差分**自动覆盖**脚本屏（`kind='script'`），零新事件。

### 6.2 Esc 语义（字节码实证）

`Screen.keyPressed` 链（26.3 `KeyEvent.isEscape` ↔ 1.21.6 `keyCode==256`，两节点 javap -c 一致）：

1. **Esc 检查最先**：`shouldCloseOnEsc()` → `onClose()` 返回 true（焦点控件不得先于 Esc）；
2. 否则 `AbstractContainerEventHandler` 分发给焦点控件；
3. 否则方向键/Tab 导航。

宿主覆写：

- `shouldCloseOnEsc()` → `spec.closeOnEsc`；`isPauseScreen()` → `spec.pause`。
- **屏级 `onKeyPress` 派发点**：`super.keyPressed` 返回 false 且会话仍存活时才派发（Esc 已关闭则跳过；控件/导航已消费则不派发）；`closeOnEsc=false` 时脚本可拦截 Esc 自行 `close()`。
- 鼠标链：控件（super）→ 屏级 `onMouse*`；`charTyped`：控件 → 屏级。**控件消费优先**，屏级回调返回 truthy 向上传播为"消费"。

### 6.3 reloadScreen

`gui.reload()` = adopt live 状态 → 按 spec 重建控件（同会话、回调与 owner 不变）。备选"重置为 spec 初值"语义差异标注为微调项（§13-6）。resize 触发的 vanilla `init()` 重建走同一 adopt 路径（不丢键入）。

### 6.4 与现存屏幕面的关系

- `/neomacros errors` 查看器：**改名共存**——现 `ScriptScreen`（查看器）迁为 `ScriptViewerScreen`（纯内部类，非 guest 可见），`ScriptScreen.java` 文件按 G-003/G-035 落点转为**脚本建屏宿主**（guest `BuiltScreen.wraps` 仍标 Mojang `…screens.Screen`，不暴露自有类名）。改名仅动 `NeoMacrosFabric:1073` 一处调用。
- `player.screen` 只读面：零语义改动（§2.3）；脚本屏走 default 分支返回基类快照。
- 游戏内 open/edit 命令已删（§1.3），**不恢复、不冲突**；若将来恢复，建议基于 `BuiltScreen` 之上做（只读查看可复用 `ScriptViewerScreen`）。

## 7. 事件回调与派发模型

### 7.1 载荷（冻结纯对象，§2.6 规则7）

| 回调 | 载荷 |
| --- | --- |
| `onMouse*` | `{pos: Pos2D, button, modifiers: string[]}`（drag 另有 `delta:{x,y}`；26.x 的 `MouseButtonEvent` 双击位透传为 `doubleClick`，1.21.6 无则 undefined） |
| `onKeyPress` | `{key: 'key.keyboard.r', code, modifiers: string[]}`（对齐 `InputKeyPressEvent` 词汇；`KeyEvent` 的 key/keycode 由 adapter 归一） |
| `onCharTyped` | `{char}`（vanilla `CharacterEvent` 不带修饰键，文档明示） |
| `onRender` | `{ctx: ScreenCanvas, mouse:{x,y}, partialTick}` |
| `onClose` | 无参（脚本闭包持有 `gui` 即可；compat 需要的 IScreen 实参由 compat 自身包装提供） |
| 控件 `onClick` | `{id, type}` |
| 控件 `onChange` | `{id, type, checked?/value?/text?}`（值字段按类型） |

### 7.2 执行模型（**推荐，拍板项 §13-4**）

- **同步、主线程、看门狗**：控件回调与屏级输入/close 回调在触发线程（主线程）内联进 guest，经独立 `SyncWatchdog`（EventBus 同款机制，独立实例）限幅：超时只记日志（3s 节流，ErrorPresenter 通道可复用），**异常吞掉、按未消费继续**（`FabricLifecyclePort.runSafely` 惯例）。
  - 理由①：compat 需要 JsMacros 的同步语义（`click()` 后立刻可见状态、`onMouseDown` 返回消费位）；异步队列给不了返回值。
  - 理由②：`onSync` 已证明 guest 可被主线程跨线程内联调用。
- `onRender` 每帧同步：必须在抽取期执行（无法异步），预算文档写明"≤1ms，重活自己降频"。
- **再入安全**：回调内再调 `gui.*` 必须主线程内联执行——`MainThread.run` 在同线程需立即跑（实施首项验证 `Minecraft.execute` 再入；若不满足则在 ScreenPort 加 `isOnMain` 短路）。
- 消费语义：输入回调 truthy = 消费（向 vanilla 返回 true）；`onClose/onRender` 返回值忽略。
- 不进 EventBus：会话本地回调非全局事件（隔离）；全局只留既有 `screen:*`。

## 8. 渲染与版本接线

### 8.1 抽取链（T-301 基础上的扩展）

```text
host.extractRenderState(extractor, mouseX, mouseY, partialTick)   // ≥1.21.11
host.render(graphics, mouseX, mouseY, partialTick)                // <1.21.11（//? 换支，同现 ScriptScreen）
```

```java
        void stateChanged(String controlId, ControlState state);   // 控件内变化 → facade 缓存
        void closed();                          // 会话终态，幂等（任意路径）
    }

    /** 主线程开屏（内部 MainThread 跳）；不可用/超时 → 抛或返回 null（facade 归一为同步 throw）。 */
    Long open(java.util.Map<String, Object> normalizedSpec, SessionSink sink);

    void close(long session);                   // 关闭意图（onClose→回父屏）

    void writeControl(long session, String id, java.util.Map<String, Object> patch);  // 主线程跳
    Optional<ControlState> readControl(long session, String id);   // 缓存未命中时的回读

    boolean shiftDown(); boolean controlDown(); boolean altDown();
```

## 13. 需需求方拍板

1. **入口命名**：推荐 `player.buildScreen(spec)`（与 `player.showDialog` 同形；第六轮 `neo.screen` 模块已并入 player，13 号 §5.5 字面 `screen.build` 已无挂载点）——是否接受改名回写 12 号 §4.16 / 13 号 §5.5。
2. **同步 vs Promise**：`buildScreen/close/add/remove/setControl/reload` 推荐**同步**（主线程有界跳，`Screen.close()` 先例；compat 的 JsMacros 全同步面刚性依赖；失败同步 throw）。与 12 号 §2.6 规则 3"主线程调度→Promise"字面冲突，需明示豁免（`close()` 实为既有豁免）。
3. **读写面边界**：推荐"只读面零改动 + 独立 `BuiltScreen` 会话句柄"（§2.3）；若要求 `player.screen` 对脚本屏返回 `BuiltScreen` 实例，需改 PlayerApi 分发并与 G-019 串行。
4. **回调执行模型**：推荐"同步主线程 + 看门狗 + truthy=消费"（compat 精确）；备选"异步派发"（更安全但消费语义失效、compat 需缩水）。
5. **类名**（Mojang 优先推导，可整组微调）：guest `BuiltScreen`（不沿用 JsMacros `ScriptScreen` 词，且与宿主类解耦）；控件 `Button/Checkbox/Slider/EditBox/CycleButton/LockIconButton`→简形 `LockButton`、基类 `Widget`（Mojang 实为 `AbstractWidget`）；宿主 product 类保留 `ScriptScreen`（现查看器更名 `ScriptViewerScreen`）。
6. **微调默认值**（无冲突，默认按下述实施，可改）：`pause=false`（防单机暂停卡 e2e tick）、`reload` 保留 live 状态（adopt）、单 `ControlSpec` 判别式 record、`onRender` 画在控件之上、富文本标题缩水为纯文本。
