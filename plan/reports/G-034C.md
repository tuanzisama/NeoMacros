### 脚本面（新增部分，G-034/034B 直接继承）

```ts
interface Draw2DElement {                       // 继承 Alignable + RenderElement 契约，成员声明在本类
  // ---- 对齐（G-034C 新增）----
  alignHorizontally(alignmentOrOther: string | Draw2DElement,
                    alignmentOrOffset?: string | number,
                    offset?: number): Draw2DElement;
  alignVertically(alignmentOrOther: string | Draw2DElement,
                  alignmentOrOffset?: string | number,
                  offset?: number): Draw2DElement;
  align(horizontalOrOther: string | Draw2DElement,
        alignmentOrOffset: string | number,
        verticalOrHorizontalOffset?: string | number,
        verticalOrVerticalOffset?: string | number,
        verticalOffset?: number): Draw2DElement;
  moveToX(v: number | string): Draw2DElement;   // 保 y 原始形态（百分比继续 reflow）
  moveToY(v: number | string): Draw2DElement;   // 保 x 原始形态
  readonly scaledRight: number;                 // = scaledLeft + scaledWidth（失效 undefined）
  readonly scaledBottom: number;                // = scaledTop + scaledHeight
  // ---- 已有（本批 A，8 个）----
  moveTo(x, y): this;  readonly zIndex: number;
  readonly scaledWidth: number;  readonly scaledHeight: number;
  readonly scaledLeft: number;   readonly scaledTop: number;
  readonly parentWidth: number;  readonly parentHeight: number;
}
// 语义速记：
//   parent 形:  alignHorizontally('left'|'center'|'right'|'n%')  → 相对父盒（层视口），n% 占"自身用剩空间"份额，offset 加在结果上
//   sibling 形: alignHorizontally(other, '<this>On<other>'[, offset]) —— 如 'leftOnRight'/'centerOnCenter'；裸词 = 两侧同锚
//   align 四形: (h,v) | (h,hOff,v,vOff) | (other,h,v) | (other,h,hOff,v,vOff)
//   不支持的父盒词 → 静默不动；畸形兄弟词 → throw；失效 → 读 undefined / 写 throw（沿基类契约）
```

## 关键设计决策（实施期）

1. **契约接口 + 方法体落声明面（本批最重要的结构裁定）**：`Alignable`/`RenderElement` 是**宿主侧契约接口（非 `@ApiClass`）**，16 个新成员的方法体全部**声明在 `Draw2DElement` 类上**。证据链：NeoMacros-Docs `ModelExtractor.classModel` 只取 `type.getEnclosedElements()`（声明成员）、`extendsNameOf` 只走父类链——**接口 `default` 方法既不进类的 d.ts、也无法被 `Draw2DElement extends …` 关联**；若接口带 `B` 泛型返回还会在 d.ts 渲染成 `unknown`（DoD"d.ts 无 unknown 悬空引用"）。故：接口 = 契约与 `align*(Alignable other, …)` 的参数类型载体；脚本面/文档面 = `Draw2DElement` 声明成员（设计 §4.2 的 d.ts 草图本来就是"成员全在 `Draw2DElement` 上、无 Alignable 类型"——与此完全一致）。参数类型 `Alignable` 经 `@ApiType("Draw2DElement")` 覆盖渲染，避免悬空。
2. **同名重载折叠（G-033 铁律①）**：任务卡 12 个对齐重载 → 脚本面 3 个成员（`alignHorizontally`/`alignVertically`/`align`），签名 = `(Object, Object, …)` 折叠形 + 运行时类型分派（首参 `instanceof Alignable` 定兄弟/父盒形，第二/三参 String/Number 定有无 offset 形）；缺省参由引擎 `convertArguments` 补 null。**Java 调用面不缩水**：12 个任务卡调用形以 `@ApiInternal` 宿主重载原样保留（`alignHorizontally(String)` 等，G-033 `Box.setColor(long)` 先例）——内部方法被引擎 `handleShape` 与文档管线双重过滤，**每名唯一绑定、顺序确定**，G-032B 的 fluent 链与新对齐面在同一键表内零冲突。
3. **对齐语义口径（JsMacros javadoc 逐条还原；上游源码体两次拉取失败，公式级还原、取整口径见偏离⑧）**：父盒相对 = 关键词锚在"父盒 − 自身缩放尺寸"的用剩空间上（`left/top`=0、`center/middle`=截半、`right/bottom`=满额、`n%`=份额），offset 加在结果；兄弟相对 = `<this锚>On<other锚>`，`x = other原点 + other锚 − this锚 + offset`，百分比锚按**各自元素尺寸**取份额；不支持的父盒词静默不动、畸形兄弟词抛 `IllegalArgumentException`、带 `%` 非整数抛 `NumberFormatException`（与 dump javadoc 的 throws 表逐条对齐）。
4. **裸词同锚默认**：兄弟形单段词（如 `align(panel, 'center', 'center')` 的 `center`）按"两侧同锚"解析（`center` → `centerOnCenter`）——上游类级 javadoc 官方示例 `label.align(panel, "center", "center")` "put in the middle of the rectangle" 只有此解释可通（无源码体，测试按此锁死，见偏离⑦）。
5. **`moveToX/moveToY` 保原始坐标**：另一轴取 `spec.y().raw()`（而非求值整数）——百分比坐标经单轴移动后继续随视口 reflow（JsMacros 无百分比坐标，属 NeoMacros 强化；绝对坐标两口径同值）。实现走 `moveTo` → `setPos` → `ensureAlive`，失效语义与基类 setter 完全一致。
6. **非泛型 `Alignable`（`B` → `Draw2DElement`）**：任务卡 `Alignable<B>` 的自返回型固定为 `Draw2DElement`（G-032B 决策8"fluent 返回基类型"同口径；子类实例运行时仍返回 `this`）。附带技术收益：接口与类方法擦除签名完全一致 → **不生成 javac 桥接方法**，`getMethods()`/`handleShape`/注解门禁面零合成方法噪声。
7. **`RenderElement` 最小化**：契约只含 `getZIndex`（任务卡非 D 成员即此一个）；`render` 判 D 不声明（javadoc 写明裁定与理由）；不引入上游 `Renderable`/`mc` 静态字段（不在任务卡，且 raw `Minecraft` 违铁律）。
8. **`RenderElementBuilder` 不建类**：G-001 §4.6 + §11 拍板②（G-032B `Builder` 同款裁定）；`build`/`buildAndAdd` 判 D 的能力承接写清在表 #27/28。
9. **失效传播**：派生边读（`getScaledRight/Bottom`）null 安全（任一输入 null → null）；对齐/moveToX/Y 首行 `ensureAlive()`（`IllegalStateException: element no longer valid`，与基类 setter 同消息）；对齐**已失效兄弟**读几何 → 同样 `IllegalStateException`（`size(Integer)` 守卫）。

## 偏离清单（与 JsMacros / 任务卡 / 设计稿）

| # | 偏离 | 理由 |
| --- | --- | --- |
| ① | `Alignable`/`RenderElement` 为**宿主侧契约接口**，不加 `@ApiClass`、不进 d.ts 类型表 | 设计 §4.2 d.ts 草图无 Alignable 类型（成员全在 `Draw2DElement`）；docs 结构约束（决策1）；脚本零感知——成员经句柄可达（e2e 实测），`instanceof Alignable` 宿主/测试可用 |
| ② | 12 个对齐重载 → 3 个脚本成员（Object 折叠 + 类型分派）；Java 调用形由 12 个 `@ApiInternal` 宿主重载承接 | G-033 铁律①（`handleShape` 按名 `putIfAbsent`，重载只留一个且顺序不定）——折叠是**绑定确定性**的唯一解；`@ApiInternal` 重载被引擎/文档双重过滤，脚本面与 d.ts 均只见折叠成员 |
| ③ | `moveToX(int)`/`moveToY(int)` → `Object`（`number \| string`） | G-032B 偏离③同源（§3.4 百分比坐标类型放宽）；`int` 实参照常工作 |
| ④ | 契约接口 getter 返回 `Integer` 装箱（任务卡字面 `int`） | G-032B 偏离②同源（失效读 `undefined` 需要装箱）；且接口签名必须与类实现**逐字一致**（否则抽象方法不被实现/产生桥接） |
| ⑤ | 上游 `default` 方法（`getScaledRight/Bottom`、12 对齐、`moveToX/Y`）在接口侧为**抽象契约**、实现体在 `Draw2DElement` 声明面 | 决策1（docs 只取声明成员 + 继承测试"引擎面 = 基类面"保持绿）；语义与上游 default 完全一致，只是归属类不同 |
| ⑥ | 设计 §4.2 的 `alignTo(other, opts?)` / `align(opts?)` 对象糖**未落** | 任务卡 12 签名的字符串形 1:1 覆盖全部能力（opts ↔ string 一一对应）；compat 桥（G-004）按 JsMacros 字符串形调用，对象糖非必需；对象参数经引擎 `Object` 桥为中立 Map，收益低。留作可增量补的糖（不阻塞 G-034/034B） |
| ⑦ | 兄弟形裸词 = 同锚默认（`'center'` → `centerOnCenter`） | 上游官方示例唯一可通解释（决策4）；上游源码体拉取失败（GitHub raw 两次超时/重置），按 javadoc 公式级还原；如后续拿到源码可逐位校准 |
| ⑧ | 取整口径：关键词 `center` = 用剩空间截半（整除）；百分比 = `Math.round`（与 `ElementSpec.Coord.resolve` 同源） | 同⑦（无源码体）；测试按此锁死，行为确定 |
| ⑨ | 接受 `middle` 为 `center` 同义词（两轴） | 设计 §3.4 `Align` 词表含 `middle`、JsMacros 垂直词表用 `center`——两者同时接受为超集，互不破坏 |
| ⑩ | 新增 12 个 `@ApiInternal` 宿主重载（不在 28 签名内） | 决策2；任务卡外新增但**零脚本面/零文档面**，G-033 `setColor(long)` 同款先例 |
| ⑪ | `parsePercentage` 以 `@ApiInternal public static` 落在接口上（脚本/文档不可见） | 设计 §3.4"不暴露静态方法"的字面执行：接口静态方法本就不被实现类 `getMethods()` 继承（引擎天然不可达），`@ApiInternal` 再过文档门——既满足任务卡"成员存在"，又满足"不暴露" |

**与任务卡冲突的裁定**：任务卡 `classes: [Alignable, RenderElement, RenderElementBuilder]` 中 `RenderElementBuilder` 判"不建类"（拍板②，G-001 §4.6 明判，同 G-032B `Builder`）；`render` 判 D（零 raw 铁律）；`parsePercentage` 判 D（设计明判不暴露）——均为"设计稿优先"（G-032/G-032B 同款裁定口径）。

## 给 G-034/034B 的父类 API 契约（基类 API 稳定承诺）

1. **继承面**：`Draw2DElement` 现为 `implements ScriptHandle, Alignable, RenderElement` 的开放基类——组件子类（`Draw2DText/Rect/Line/Image/Item`）**自动获得全部对齐/几何/z 面**，无需也**不应**重声明同名成员（重声明会把 `handleShape` 的绑定类挪到子类，破坏"引擎面 = 基类面"继承测试）。fluent 一律返回基类型 `Draw2DElement`（子类实例上 `assertSame` 仍是 `this`，链式无感——G-032B 决策8 口径）。
2. **状态模型不变**：不可变 `ElementSpec` + `Draw2DElement.Backend` 五法（`spec/publish/viewportWidth/viewportHeight/disposed`）+ `protected backend()` 扩展缝——G-034 加组件字段（`withColor/withText/...`）只改 `ElementSpec` 与 `HudScene.emit`，**基类文件不动**。子类 mutator 经 `backend().publish(...)` 出版即自动获得失效复查（`Backend.publish` 契约"单元已亡时抛"），与基类 `ensureAlive()` 同消息。
3. **对齐数学可直接复用**：子类如需组件特化对齐，可读 `getScaled*/getParent*` 与 `bounds`（同源口径）；`Alignable.parsePercentage`（宿主侧）可复用百分比解析。**注意**：对齐读兄弟用 `Alignable` 接口类型——任何 `Draw2DElement` 子类天然可作 `other` 传入。
4. **脚本面稳定项**：每名一脚本绑定（勿在子类加同名重载）；0 参 `get*/is*` → 属性（`scaledRight` 等已占键）；新成员必带三注解（`AnnotationCompletenessTest` 扫 `Draw2DElement` 声明面）；`@ApiInternal` 成员不进脚本/文档（若子类需要宿主捷径，沿本批口径标 `@ApiInternal`，并注意 `Draw2DElementInheritanceTest` 的 triple 循环已按"跳过 internal"口径锁定）。
5. **失效语义不变**：读属性 → `undefined`、写方法 → `IllegalStateException: element no longer valid`、`disposed` 常读——对齐面 100% 并入该表（测试锁死）。
6. **零端口流量承诺**：对齐/几何/z 全部 core 内完成；组件 paint 分支（G-034 的 `emit` 扩展）同样不得触端口（e2e `events()` 断言模式可复用）。
