## 偏离与回写

1. **新脚本类型 `Enchantment`（任务卡落点外的竖切必需）**：36 签名中 8 个带参（`canBeApplied`×2 `isCompatible`×2 `conflictsWith`×2 `getRomanLevelName(int)` + `removeEnchantment`/`addEnchantment` 的句柄形态），而 **record 在 guest 侧只出分量不出方法**（`Payloads.snapshot` 把 record 拍成 `{分量}` map，`GraalJsEngine.asGuestValue` 走 `ProxyObject.fromMap`）——带参成员必须落在 `ScriptHandle` 上，故新建 `core/api/types/Enchantment.java` + `registerGuestType`（`ApiCompletenessSurface.CLASSES` 同步）。落点文件 `EnchantmentData.java` 因此**零改动**（T-420 形态保持 `EnchantmentData(id, level)`，继续作为 `ItemStackData` 的中立分量）。
2. **写面落 `ItemStackBuilder` 且返回 Promise**：按任务卡验收"Builder 写面 Promise"与 G-024 拍板"写动作一律 `setXxx` → Promise"，14 个写签名全部返回 `CompletableFuture<ItemStackBuilder>` + `@ApiType("Promise<ItemStackBuilder>")`（resolve 值即构建器，`await` 后可继续链式/`build()`）。**写是即时生效的**（本地数据无主线程跳，future 已落定），这样 fire-and-forget 与 `await` 两种写法都成立。**与 0.2.0 既有同步链式写（`count/name/lore/enchant/unbreakable`）风格不一致**——本批按验收执行，是否回退为同步链式需需求方拍板（见遗留④）。
3. **写通道 = 构建器草稿，不是"返回新栈"**：`ItemStack` 不可变（DATA 铁律），G-027 交接待落的 `getCreative()` 落成 `stack.creative: ItemStackBuilder`（`copyFrom` 底稿）。JsMacros `getCreative()` 返回"同一栈的可变包装"，NeoMacros 语义等价物是"以该栈为底稿的草稿，`build()` 产出新栈"——差异已写进 javadoc。
4. **`enchant`（0.2.0）与 `addEnchantment`（本批）语义分工**：`enchant(id, level)` javadoc 明写 "repeats allowed"（追加、允许重复），本批不改其既有行为；`addEnchantment(idOrHandle, level?)` 按 Mojang `ItemStack.enchant` 做同名覆盖。两法并存的取舍与"统一为覆盖语义"的建议见遗留⑤。
5. **`addLore` 变参 → 单参（标量或数组）**：引擎 `GraalJsEngine.convertArguments` 按 `method.getParameterTypes().length` 取参，Java 变参在 guest 侧只拿到形参数（1 个），且 `Method.invoke` 对"非数组末参 + 变参方法"直接抛 `IllegalArgumentException: argument type mismatch`（已用最小复现验证）。故本批把 `addLore(Object... lore)` 落成 `addLore(line | lines)`：`addLore('a')` 与 `addLore(['a','b'])` 均可用；**`addLore('a','b')` 会静默只取首参**——该限制属引擎层，见遗留③。
6. **形状偏离两处**：`getAcceptableItems(): ItemHelper[]` → `string[]`（无 `Item` 句柄类，同 G-027 口径）；`getConflicting/CompatibleEnchantments(ignoreType)` 去掉 JsMacros 自述无作用的形参（并面）。
7. **`stack.enchantments` 元素类型变化**：`EnchantmentData` record → `Enchantment` 句柄。`.id`/`.level` 读法不变，但 `JSON.stringify(entry)` 从 `{id, level}` 变为句柄成员键集（含全部只读属性）。`ItemStack.toJSON()` 仍输出 `{id, level}`（内部字段未变）。**另一面保持不动**：`player.inventory` 附魔台菜单的 `enchantments` 仍为 `{id, level}[]`（13 号 §5.10 该行口径；宿主在 `PlayerApi`，本任务禁改）——两面形状暂不一致，回写建议见遗留⑥。
