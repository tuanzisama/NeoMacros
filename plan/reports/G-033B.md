## 120 签名逐成员 A/B/D 映射

> A = 桥接现有面；B = 新增包装成员（含**改名/换型/折叠**落地，调用形参变化在证据列写明）；D = 不映射。

## 关键设计决策（实施期）

1. **三个新 spec record 而非改既有**：`CameraTrace/EntityTrace/Panel` 加入 `ShapeSpec` sealed permits，`Box/Line/Trace/Surface` 零改动——任务卡"新 record 避开既有破坏"；legacy `Trace/Surface` 仅即时原语继续使用，`alwaysOnTop` 选择器对它们保持 false（历史标准桶行为不漂移）。
2. **entity 绑定 = 双轨**：组件存 `EntityApi.Entity` 句柄（`getEntity` 读面）+ 绑定时经 `getUuid()` 捕获 `UUID` 进 spec；适配器每帧按 UUID `entitiesForRendering()` 重解析（复用 `traceLine` 样板），实体缺席 → spec 带 UUID 但画不出 → 跳过（不删元素，JsMacros"消失即停画"的宽容版）。
3. **面板几何全在适配器逐帧重算**：`Panel` spec 携带 origin/尺寸/旋转/轴心/billboard/绑定，而非烘焙四角——绑定实体的面板每帧才能跟着动；旋转按 y→x→z 度序、`rotateCenter` 切换 pos=角点/中心双语义（setPos javadoc 同文）、`renderBack=false` 用面法线·摄像机向量点积剔除、`rotateToPlayer` 用摄像机 yaw/pitch 直接构造 billboard 基（绕过旋转序）。
4. **节点差异两段独立条件**（javap 实证见下节）：`>=26.1` 切 Camera 访问器（`position()/yRot()/xRot()` vs 1.x `getPosition()/getYRot()/getXRot()`）、`>=26.2` 切 GameRenderer 取相机（`mainCamera()` vs `getMainCamera()`——26.1.2 仍是旧名，首轮只判 `>=26.1` 在 26.1.2 编译红，javap 三节点后拆两段）。
5. **像素面即时计算**：`getWidth/getHeight` 按"短边=minSubdivisions、另一边按宽高比截断"现算（无缓存）——因此 `init()` 无事可做（D 的依据之一）。
6. **光照三态只存不渲**：`setFullBrightLight/setWorldLight/setLight` 状态 1:1 落地（成员表无 getter，与 JsMacros 同），但双管线以平色渲染（gizmo/lines 无光照通道）——fullBright 即现状，world/fixed 见偏离③。
7. **协变覆盖保型**：`EntityTraceLine.build/buildAndAdd` 覆盖父类同签名（返回收窄），不产生第二键；`TraceLine` 的 fluent setter 返回 `TraceLine`（与 JsMacros 元素侧声明一致），脚本动态派发无感、Java 链上需语句式——e2e/core 测试写法即证。
8. **`@ApiInternal` Java 捷径**：`addDraw2D(x,y,z)`、`addEntityTraceLine(entity,color)` 供 Java/测试调用（handleShape 跳过 internal，G-033 `setColor(long)` 同款），脚本面只有全参形。
