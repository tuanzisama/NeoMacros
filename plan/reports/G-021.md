## Loom 类设计（新建，C 类）

```java
@ApiClass(name = "LoomInventory", kind = ApiClassKind.HANDLE,
        wraps = "net.minecraft.world.inventory.LoomMenu")   // 13 §4 拍板形态
@ApiSince("0.5.0") @ApiMC("*") @ApiLoader("*")
public static final class LoomInventory extends Inventory {
    LoomInventory(String title, String kind, int size) { ... }   // 包私有，同兄弟类
    List<String> getPatterns();                                   // → 属性 patterns
    CompletableFuture<Boolean> selectPatternId(String id);
    CompletableFuture<Boolean> selectPattern(int index);
}
```

- **kind**：`openByKind` 新增 `case "loom"`（`menuKind(LoomMenu)` 已在 G-019/G-020 返回 `"loom"`，此前落到基类）。
- **wraps**：`LoomMenu`（13 §4 原文）。
- **构造**：与 `VillagerInventory`/`HorseInventory` 同形（包私有 `(title, kind, size)`），`NeoMacrosFabric`/`E2ERuntime` 各补 1 行 `registerGuestType("LoomInventory", …)`（同 G-019 连带先例）。
- **图案供给**：`LoomMenu.getSelectablePatterns()`（无参公有，两节点同名同型）即「图案槽物品的可选图案、按选择顺序」——与 JsMacros `getPatternsFor(slot2)` 同源（该私有逻辑就是它的缓存），因此**无需**引入 `PROVIDES_BANNER_PATTERNS` 组件的 1.21.6(`TagKey`)/26.3(`HolderSet`) 类型分歧分支（javap 反查确认该分歧存在但被本路径规避）。
- **选择门**：`LoomScreen.displayPatterns`（私有 boolean，两节点同名）经 `LoomScreenAccessor` 读取，与 JsMacros `jsmacros_canApplyDyePattern()` 同义；`clickMenuButton(player, index)` 本地校验 + `handleInventoryButtonClick` 走原版按钮路径（与 G-020 `selectRecipe`/`doEnchant` 同款）。
- `selectPatternId` 在 facade 内由 `patterns.indexOf(id)` 解析为序号（供给列表小、顺序与 `clickMenuButton` 索引空间一致）。

## 偏离与回写（需需求方确认后回写 12/13 号与 docs 类页）

1. **`getShownItems` → `shownItems`（13 §4 原写 `items*`）**：`items` 已被基类 `Inventory.items`（槽位→堆 Map）占用，按 G-020 `getSmeltedItem` 先例更名。
2. **`getTabNames/getTabTexts` → `tabNames`/`tabTexts`（13 §4 合并写作 `tabs*`）**：两个成员不能共用一个名；`getTabTexts` 产出**纯文本** `TextComponent`（页签显示名均为无样式 translatable，不带事件/样式；如需完整 Component 样式需端口改携 `ChatComponent`）。
3. **horse 三谓词保留 JsMacros 原名**：`canBeSaddled`/`hasArmorSlot`/`hasChest` 未采用 13 §4 的 `isSaddleable*`/`canWearArmor*` 改名——引擎属性化规则只剥 `get/is` 前缀，`can*/has*` 无参成员在本库既有形态即方法（G-020 `canCraft()`/`canBrewCurrentInput()` 先例），保留原名使 compat 零翻译；`isSaddled` 按引擎规则落属性 `saddled`（与实体面 `isSaddled()` 同词根）。**建议回写 13 §4。**
4. **`destroyAllItems` 按原版 46 槽循环**，非 JsMacros 的 `handler.slots.size()`（创造菜单约 91 槽，超出玩家菜单的包会被服务端拒绝）——取原版 trash-all 语义；compat 如需逐字复刻 JsMacros 行为需自行换算。**建议回写 13 §4。**
5. **`isLeveled` 按 JsMacros 实实现 `showProgressBar()`**，非 13 §4 猜测的 `level > 0`（13 §4 该行未标 ⚠ 但与 JsMacros 源码不符）。**建议回写 13 §4。**
