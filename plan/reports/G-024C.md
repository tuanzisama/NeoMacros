## 命名与形态决策

1. **句柄不变**：`MusicOptions` / `SkinOptions` 由 G-024 建好并注册（`NeoMacrosFabric.registerGuestType`、`E2ERuntime` 各 7 类已含本批两类），本批只在其上加成员，**未触碰任务卡外的注册文件**。
2. **音量词表 = `SoundSource.getName() + "Volume"`**：`masterVolume / musicVolume / recordVolume / weatherVolume / blockVolume / hostileVolume / neutralVolume / playerVolume / ambientVolume / voiceVolume / uiVolume`。Mojang 自己的分类名就是 `SoundSource.getName()`（选项 id `soundCategory.<name>`、`volumes` 映射键同源），因此 `music.recordVolume` ↔ `volumes.record` 同形；JsMacros 的 `getRecordsVolume/getBlocksVolume` 复数形改名为单数（`playerVolume` 两者本就一致）。
3. **`volumes` 映射键 = `SoundSource.getName()`**（`master/music/record/weather/block/hostile/neutral/player/ambient/voice/ui`，共 11 键），与 JsMacros `getVolumes()` 逐键一致；值为**已存滑块值**（见「语义差异」①）。
4. **皮肤部件词表 = `PlayerModelPart` id 的 camelCase**：`cape/jacket/leftSleeve/rightSleeve/leftPantsLeg/rightPantsLeg/hat`；`leftPants → leftPantsLeg` 按 Mojang 官方 id `left_pants_leg` 改名。
5. **无参状态一律属性、写动作一律 `setXxx` → `Promise`**（沿 G-024/G-024B 拍板）：`areSubtitlesShown → showSubtitles`、`isCapeActivated → cape`、`toggleCape → setCape`、`toggleMainHand → setMainHand`、`getAudioDevices → audioDevices`、`getVolumes → volumes` 全部归一。
6. **读写成对 + 回读校验**：本批全部写动作复用 G-024 的 facade 单点 `writeOption(name, value)` → `ClientPort.setOption` 主线程落 `CompletableFuture` → `verifyValue(component, …)` 比对（数值按 double 比、字符串忽略大小写）。**每分组 ≥1 个写→回读往返断言**见「测试」。
7. **`setOption` 扩成按名分派**：`Options` 上没有 `masterVolume()` 这类按名访问器（音量在 map 里）、皮肤部件根本不是 `OptionInstance`，因此 `FabricClientPort.setOption` 在反射路径之前先查 `soundVolumeOf(name)` / `modelPartOf(name)` 两张表。这仍属「按选项名写一个 option-backed 值」——音量与模型部件都持久化在 `options.txt`（音量键 `soundCategory.<name>`、模型部件键 `modelPart_<id>`，两条 concat 配方 javap 已核）。**好处是 `writeOption` 单点与两个 stub 的通用 `withOption` 都不用改**：core/e2e stub 只需补 `audioDevices()` 与 `OptionsData` 分量。
8. **闭集 / 量程值在 adapter 落写之前校验**（与 `setCameraMode` 越界 reject、`convertOptionValue` 枚举解析同层）：
   - 音量 `0..1`：`volumeLevel()` 先校验再 `set()`。理由见「语义差异」③。
   - `soundDevice` 可用性：`convertOptionValue` 里比对 `getAvailableSoundDevices()`。理由见「语义差异」④。
   - `mainHand`：沿 G-024B `setChatVisibility/setNarrator` 形态，交给 `convertOptionValue` 的 `Enum.valueOf`（未知名抛错 → reject），不另写分支。
   两个测试 stub 各加了一段同文案的 `invalidWrite` 镜像（与 `WritableClient.setLanguage/setCameraMode` 镜像 adapter 契约的既有做法一致），使 reject 路径在 core 可断言。
9. **缺席语义**：`options()` 空 → 两组标量属性全部 `undefined`、`volumes = {}`、`audioDevices = []`；写动作 reject（`game options are unavailable`）。
10. **注解**：新增成员全部 `@ApiSince("0.5.0")` + `@ApiLoader("*")` + `@ApiMC("*")` 显式三注解，读属性另加 `@ApiReadOnly`；注释英文 + `@zh`（`AnnotationCompletenessTest` 门绿）。
11. **`OPTION_NAMES` 白名单扩展**（G-024B 遗留④的本批口径）：新增 18 个名——11 个音量名 + 7 个皮肤部件名；`soundDevice` / `mainHand` / `showSubtitles` 原本就在白名单内。`optionValue` 同步加了两张表的分支，`client.option('masterVolume')` / `client.option('cape')` 因此可读。

## 与 JsMacros 的语义差异（有据）

1. **音量读值 = 已存滑块值，不是主音量相乘后的有效值**：JsMacros 在 `>1.21.5` 分支里读 `getFinalSoundSourceVolume(cat)`（非主分类返回 `raw(cat) × raw(master)`，`getFinalSoundSourceVolume` 字节码已核），因此 `setMusicVolume(0.5)` 后若 master=0.5，`getMusicVolume()` 返回 0.25、往返不成立。NeoMacros 读 `getSoundSourceOptionInstance(cat).get()`（`OptionInstance<Double>` 原值），**写→回读必然成立**；master = 1.0（默认）时两者一致。
2. **音量与皮肤部件的改名**：`recordsVolume → recordVolume`、`blocksVolume → blockVolume`（Mojang `SoundSource.getName()` 单数）；`leftPants → leftPantsLeg`、`rightPants → rightPantsLeg`（Mojang `PlayerModelPart` id）。compat shim 需按此表换算。
3. **越界音量 reject 且不动状态**：javap 1.21.6 与 26.3 一致——`OptionInstance.set` 在 `ValueSet.validateValue` 返回 empty 时走 `orElseGet`，回落到 `initialValue`（`method_42403` 打 error 后 `getfield initialValue`；音量滑块构造期 `dconst_1` → **1.0**），即**写 1.5 会把该分类重置成 1.0 再谈校验**。NeoMacros 在 `volumeLevel()` 先把 `0..1` 挡掉，被拒的写不碰状态；JsMacros 直接 `.set(volume)` 且不校验，越界会静默把音量顶到 1.0。
4. **未知音频设备 reject 且不动状态**：soundDevice 的 `LazyEnum.validateValue`（`Options.method_42516`）对「运行中 + 非空 + 不在可用列表」返回 empty → 回落到 `initialValue=""` 并触发 `onValueUpdate`（`method_42509`：`SoundManager.reload()` + 播放按钮音）。NeoMacros 在 `convertOptionValue` 里先比对 `getAvailableSoundDevices()`，未知标识直接 reject、**不改已存选择也不触发重载**；JsMacros 是「不在列表就写 `""`」——未知设备**静默切回默认并成功 resolve**。
5. **`toggleMainHand(String)` → `setMainHand(String)` 只认 `left`/`right`**（大小写不敏感）：JsMacros 是 `equals("left") ? LEFT : RIGHT`——**任何非 "left" 的值都会被写成右手**；NeoMacros 未知名 reject（沿 G-024B「枚举写解析未知名 reject」口径）。
6. **皮肤部件写入只改本地掩码**：`Options.setModelPart` 字节码（两节点一致）仅 `Set.add/remove`，**不落盘、不发包**；JsMacros 同样只调 `setModelPart`。持久化走本批既有 `options.saveOptions()`，服务器侧在下一次客户端信息下发时生效——与 vanilla 自己的皮肤设置页行为一致，NeoMacros 不额外广播。
7. **`showSubtitles` 双组共享**：`music.showSubtitles` 与 `accessibility.showSubtitles` 是同一 `OptionsData.showSubtitles` 分量（同 `chatOpacity` 在 chat/a11y 共享的既有形态）。
8. **`getAudioDevices()` 首项是空串**：空串是 vanilla `soundDevice` 的默认设备标识（`DEFAULT_SOUND_DEVICE`、构造期 `initialValue=""`、`method_42516` 对 `""` 无条件放行），JsMacros 的 `getAudioDevices()` 也显式前置 `""`。保留它使 `audioDevices.includes(soundDevice)` 恒真、`setSoundDevice("")` 恒合法。

## 1.21.6 与 26.x 的 API 差异（本批触碰，javap 各查一次）
