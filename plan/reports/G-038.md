## 关键设计决策（实施期）

1. **注册表归 `HudApi` 实例 + `CustomImage` 静态 sink**：CE 把 `IMAGES` 放 `CustomImage` 静态字段，但 owner 卸载需要 `LoadTracker/OwnerScope`（HudApi 已有 `ownerProbe` 测试缝）。故注册表活在 HudApi（与 `layers` 同锁同生命周期），`CustomImage` 构造末尾经 `installRegistry` sink 通知——两侧各得其所，`FakeOwner` 可完整驱动画布登记的卸载断言。sink 单槽后装覆盖（生产/E2E 各只有一个 HudApi；core 测试顺序执行，旧实例登记无害）。
2. **去重 = create-or-returns 同句柄；占位上传 best-effort**：同 owner 同名二次 `hud.texture()` 不碰端口（断言"恰一次 puttexture"）；空白占位 `putTexture` 失败静默（`Texture.update()` 是权威等待点，G-030 偏离④同口径）。`texture()` 命中已有登记时**绝不**重传——否则会把并入画布的 GPU 内容清成空白。
3. **画布并入（adopt）尺寸以画布为准**：同标识下画布构造已上传自己的像素，登记的 `width/height` 同步为画布尺寸（`@ApiInternal adopt`），避免 `texture()` 占位 1×1 与真实 64×64 槽位读数矛盾。
4. **标识符全局按名（与 CE 同）**：`neomacros:image/<name>` 不嵌 owner（标识路径字符集装不下任意模块名，且 CE 注册表本就全局）；owner 隔离发生在**登记层**（键/列表/卸载回收）。跨 owner 刻意同名会共享 GPU 槽、一方 dispose 影响另一方——javadoc 已写明，列为遗留 3 的使用约定。
5. **`dispose()` 同步 void（拍板⑥字面）**：端口 `removeTexture` 返回 future 但句柄面不暴露等待（`FabricRenderPort` 主线程落定，`release()` 对未知 id 天然 no-op）；幂等由 `disposed` 挡板 + `removeTextureEntry` 对缺失键 no-op 双保证。
6. **`update(Image)` 入参 = PNG 快照 `Image`**：G-001 `update(image)` 字面；解码走 core 内 `ImageIO`（G-030 AWT 后端同款，单测友好）。解码/入参/已失效 = 同步 throw（BuiltScreen "closed 后 mutator throw" 先例），上传失败 = promise 拒绝。
7. **`createTexture` 不建 `hud.createTexture` 成员**：见映射表 #4——引擎按名折叠使两种重载形态无法共存，且 CE 该成员本就是 `createWidget` 别名 + 注册副作用，`new CustomImage`（G-030）+ sink 恰好一次给全。
