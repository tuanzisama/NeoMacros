## 版本差异与 javap 证据

- 命令：`javap -cp <loom named jar> <FQN>`（1.21.6 用 `minecraftMaven/.../minecraft-merged-1.21.6-loom...jar`，26.x 用 `fabric-loom/<v>` 对应 deobf/named jar；`//? if` 分支另经四节点编译+测试实证）。
- **进度时间戳客户端可读**（关键结论，避免了新 accessor）：`AdvancementProgress.STREAM_CODEC` 复合 `CriterionProgress.STREAM_CODEC`（含 `ByteBufCodecs.INSTANT`）；1.21.6 `CriterionProgress.serializeToNetwork` `writeNullable(Instant)`——服务端进度包携带条件完成时间，客户端 `getCriterion()/getObtained()` 直读。
- **进度进度方法**：`getPercent()/getProgressText()/getCriterion()/getFirstProgressDate()/hasProgress()` 在 1.21.6/26.1.2/26.2/26.3 全公有；`countCompletedRequirements` 私有（核心侧同算法复算，字节码复核 `requirements.count(任一达成)`）。
- **1.21.6 progress 字段非公有**（T-515 结论）：沿用既有 `ClientAdvancementsAccessor`（`@Accessor("tree"/"progress")`，四节点 mixin AP 校验绿）；26.3 已有公开 `tree()/progress()` 但不改动，保持单路径。
- **包/签名枢轴**（均 `//? if` 分支，参照 `AdventureModePredicateAccessor` 先例）：
  - loot 类型 `List<ResourceKey<LootTable>>`（1.21.6/26.1.2/26.2）→ `HolderSet<LootTable>`（26.3）；
  - `ResourceKey.location()` → `identifier()`（1.21.11 枢轴，`rewardKeyId` helper 内分支）；
  - 触发器包 `critereon`（1.21.6）→ `criterion`（26.1）→ `triggers` + `Criterion` 迁入（26.2+）——仅测试构造用，生产代码不触碰；
  - `ResourceLocation` → `Identifier` 类名（既有 blanket 替换，`NeomacrosNode.kt` 无需改动）。
- **toJson 编码路径**：plain `JsonOps.INSTANCE` 编码侧不需要 RegistryOps（`ResourceKey`/注册 holder 编码只写 id）；`Advancement.CODEC` 静态初始化需 `SharedConstants.tryDetectVersion + Bootstrap.bootStrap`（产品测试 `@BeforeAll`）；criteria 校验要求与 requirements 精确匹配、触发器必须是注册实例（真实客户端数据恒满足）。

1. **`Statistics`/`Advancements`/`Advancement` 补 `implements ScriptHandle`**：第七轮三句柄只有 `@ApiClass` 没有 `ScriptHandle` 标记，guest 属性面（`adv.progress`、`statistics.entries`、`advancement.title` 等拍板属性）实际走 `JavaObject` interop 代理（只读字段），属性读不出（G-028 报告已登记同类 latent「建议单开小任务批量补」）。本任务的 e2e 断言依赖属性面，按 G-028 先例就地修复；副作用：第七轮拍板的属性名恢复可读。
2. **`ApiCompletenessSurface.CLASSES` +3 类**：注解三标注门覆盖本任务改动的句柄（存量成员与新成员全部过门）。

4. `script-tests/cases/gap-api/index.js` 增 g018.* 形状断言（与 G-028 同款「缺席也计通过」口径）。
