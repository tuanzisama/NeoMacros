# DevTools 控制台改造(合并日志 + Chrome 风格 + 完整 REPL)

## Context

编辑器 DevTools 目前有三个标签:`日志`(mod log4j 纯文本输出)、`控制台`(宏 console.* 富渲染输出)、`任务`。目标:以控制台为主体,把日志合并进单一「控制台」标签,布局/交互对齐 Chrome DevTools(工具栏筛选、级别侧栏、单一时间线、底部 REPL 输入行),并移除暂停功能(滚动条贴底即自动滚动,离底即停,无 UI 开关)。

已确认的决策(两轮提问):
1. 标签结构:合并为单一「控制台」+ 保留「任务」
2. 日志与脚本 console 消息:单一时间线交错混排
3. REPL:做完整实现(编辑器输入行 + mod 端新增 eval API)
4. Chrome 式级别侧栏:做,默认隐藏,工具栏按钮切换
5. REPL 上下文:独立 devtools 会话 + 可切换到任一已加载宏的上下文("top ▼" 式选择器)
6. 给 LogEntry 补 `ts` 字段(取 log4j 事件时间),实现真正按时间交错

注意:两个仓库都有大量在途未提交 WIP(console.*/tasks/manifest 波次),本计划叠加在当前工作区状态之上,不提交、不回滚任何现有改动。

## 架构要点(已核实的关键机制)

- **eval 执行路径**:Graal Context 线程封闭,必须复用 `GraalJsSession.onLoop`(engine/GraalJsEngine.java:664,30s 超时)投递;Promise 结算复用 `importModule` 的 then-callback + CompletableFuture 模式(GraalJsEngine.java:304-351),不阻塞循环线程。**不走 `game.call`**(那是游戏主线程 5s/504 约定,与上下文循环无关)。
- **结果序列化**:复用 engine 包内 `ConsoleFormatter.node(Value)`(GraalJsEngine.java:410-417 同款用法,预算 MAX_NODES=400),产出前端已有的 `ConsoleNode` 树,`ConsoleMessage.vue` 直接富渲染。
- **REPL 历史**:eval 的输入回显与结果以合成 `ScriptConsoleEvent`(新 kind `input`/`result`,macro=`devtools` 或目标宏名)**直接 append 进 `ConsoleRing`**(product/.../web/console/ConsoleRing.java:38)——从而免费获得 SSE 推送 + 断线重放。**绕过 `ScriptConsole.dispatch`**,避免结果镜像进游戏聊天(ConsoleMirror)。编辑器按 seq 去重,HTTP 响应与 SSE 重复送达天然幂等。
- **REPL 声明持久化**:每条输入以 script-mime(非 module-mime)eval,顶层 `let/const/function` 进入全局词法环境,跨输入持久;含 `await` 的输入自动包 `(async () => …)()`;结果为 Promise 则自动 await 展开。
- **信任面**:独立 devtools 会话用 `PermissionView.ALLOW_ALL` 装配绑定(同 NeoMacrosFabric.java:1094 虚拟模块口径;编辑器设备本就可通过 writeFile 写任意宏代码,权限等价)。切到宏上下文时,该会话沿用该宏已装配的绑定树(自带其信任视图)。

## Mod 端改动(neomacros)

1. **LogEntry 加 ts**:`LogRing.Entry`/`append` 增加 `long ts`(product/.../web/log/LogRing.java:16,36);`LogTap` 传 `event.getTimeMillis()`(LogTap.java:76);wire record `web/v1/LogEntry.java` + `WebService.java:150-152` SSE 广播同步补字段;`ApiV1.logs()`(ApiV1.java:460-470)映射补字段。
2. **Engine SPI 扩展**:`core/runtime/ScriptEngine.java` 的 `EngineSession` 增加 `EvalOutcome eval(String expression)`;新增 `EvalOutcome` record(值节点 map / 抛错时 name+msg+stack / durationMs)。`GraalJsSession` 实现:script-mime eval + await 包装 + Promise 自动展开 + `ConsoleFormatter` 序列化。
3. **宏上下文 eval 入口**:`core/module/LoadedModule.java` 增加公开 `evaluate(expression)`(其 `session()` 现为 package-private,LoadedModule.java:63)。
4. **独立 devtools 会话**:core 侧新增小类(如 `core/console/DevToolsSession` 或挂在 ModuleManager):`ScriptRuntime.createContext("devtools")` + `engine.openSession(macrosRoot)` + ALLOW_ALL 绑定 + console 全局;随 web 服务/运行时生命周期关闭。
5. **新路由**:`@NmPost("/api/v1/console/eval")`(ApiV1.java):body `{target: "devtools"|"<宏名>", expression}`;target=`devtools` 走独立会话,否则 `ModuleManager.loaded(name)` → 未加载返回 404 `not_found`;eval 完成(或抛错,仍 200)后把 input/result 两条合成事件 append 进 ring,响应返回 `{entries:[inputEntry, resultEntry]}`(复用 `ConsoleResponse`)。超时 → 504 新错误码 `eval_timeout`。
6. **Backend 接线**:`PanelBackend`/`WebRuntime` 增加 `evaluateConsole(...)`(plain-thread 契约,非 game-thread);`NeoMacrosFabric` 注入会话持有者。
7. **测试与 golden**:`WebApiIntegrationTest` 增加 eval 用例(happy/抛错/未知宏 404/超时);OpenAPI golden 用 `-Dneomacros.refreshGolden=true -Dneomacros.goldenPath=product/src/test/resources/web/openapi-golden.json` 刷新(测试任务名注意 `:product:26.3:test` 口径)。

## 编辑器改动(NeoMacros-editor)

1. **types/api.ts**:`LogEntry` 加 `ts`;`ConsoleKind` 加 `'input' | 'result'`;`ApiErrorCode` 加 `'eval_timeout'`;新增 Eval 请求/响应类型。
2. **api/endpoints.ts**:`evaluateConsole(target, expression)` — 按 `createMacro` 模式(endpoints.ts:112-117,POST + JSON body,NM1 签名已覆盖 body);旧 mod 404 时优雅降级(隐藏输入行)。
3. **stores**:
   - `logs.ts` / `console.ts`:删除 `paused` 状态与 append 冻结点(logs.ts:64、console.ts:77);append 时打上共享单调 `arrival` 戳(新 `stores/arrival.ts`);`console.ts` 对 `input`/`result` kind 正常入栈。
   - 新 `stores/mergedConsole.ts`:合并计算 `mergedRows` = 日志行 + console 行按 `ts` 排序(arrival 决胜);统一级别桶映射(logs TRACE/DEBUG→verbose、INFO→info、WARN→warn、ERROR→error;console debug→verbose、log/info→info、warn→warn、error/assert→error);统一搜索(日志匹配 line/logger,console 匹配 flattenEntry);暴露各桶计数(侧栏与状态栏用);`clearAll()` 同时清两个 store;收到 `clear` kind 时同样双清。
4. **合并后的控制台标签**:删除旧 `ConsoleTab.vue`(日志面板);以 `ScriptConsoleTab.vue` 为基础改造为合并控制台(文件重命名为 ConsoleTab.vue):
   - 工具栏(Chrome 布局):宏/上下文选择器(REPL target,默认 `devtools`)、级别下拉(Chrome "Default levels" 式:详细/信息/警告/错误复选)、Filter 搜索框、右侧 [侧栏切换][清屏](删除暂停按钮与 `.tool.on` 暂停态样式)。
   - 行布局统一:`时间 | 级别 | 来源 | 消息`——console 行显示宏 id、日志行显示 logger 灰色标签、input 行显示 `› 表达式`、result 行经 ConsoleMessage 渲染(err 节点红色含 stack)。
   - 粘底自动滚动保留现有逻辑(距底 <40px 即贴底,onScroll 已有),无暂停。
   - 侧栏:新组件,各级别桶计数 + 「全部」行,点击套用过滤;默认隐藏,可见性持久化到 settings store(localStorage)。
   - REPL 输入行:新组件(底部固定,`›` 提示符,textarea 自增高):Enter 执行、Shift+Enter 换行、↑/↓ 历史导航(历史持久化 localStorage)、执行中禁用;断连或旧 mod(端点 404)时禁用并提示。
5. **registry.ts**:两项 `[{id:'console', label:'控制台', 合并组件}, {id:'tasks', …}]`;`DevToolsPanel.vue` 对失效的持久化 tab id(如旧 `scriptconsole`)回退到第一项。
6. **dev-stub/server.mjs**:补 eval 端点(回显 input/result 合成条目)与日志 ts,使 UI 可脱离游戏开发验证。
7. **docs/mod-api-pending.md**:补 eval 端点条目。

## 实施顺序

mod 契约先行(ts → SPI eval → 会话 → 路由 → 测试/golden),编辑器随后(types → stores → 合并组件 → REPL → stub),最后联调。

## 假设(如与预期不符请指出)

- eval 结果不进游戏聊天(绕过 ConsoleMirror)。
- 独立 devtools 会话为 ALLOW_ALL 信任面;宏上下文沿用宏自身视图。
- 旧 mod 无 eval 端点时输入行降级隐藏;未加载宏作为 target 返回 404。
- REPL 的 await 检测用简单启发式(源码含 `await` 即包 async IIFE),边界误判可接受。
