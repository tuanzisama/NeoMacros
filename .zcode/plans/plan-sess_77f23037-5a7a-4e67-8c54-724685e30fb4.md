# NeoMacros 重构：startup 入口 + config 块 + 任务管理器 + 侧边栏改进

## Context

需求（`C:\Projects\fabric-mod\重构.md`）：① 三大宏类型统一 `startup` 入口，清单按类型声明触发定义；② 任务管理器（活动栏+DevTools），表格展示宏任务（唯一ID、停止、历史、玩家/服务器元数据）；③ 宏侧边栏主目录行两行化。

现状缺口：入口为"顶层代码 + onKey/dispose"；按键仅按下沿（tick 轮询 consumeClick），无 keydown/keyup/修饰键；事件宏靠 `events.on` 自订阅；无任务对象/历史/玩家与服务器元数据；前端无任务面板。复用：console 功能管道（core hub → product ring → SSE）、`revealInEditor` 跳转、`.chip-key` 样式、DevTools tab 注册表。

## 已确认的需求决策（三轮提问 + 补充澄清）

1. **startup 混合语义，任务=宏实例**：service 激活时调用一次；keypress 每次按键、event 每次事件触发调用 `startup(payload)`（参数经 startup 传入）。任务表每行=宏实例（激活→停止），记录触发次数。
2. **event `on` 仅限现有 34 个内置事件**，加载时严格校验，未知名报错并列出可用值；`事件类型清单.md` 其余事件留待后续版本。
3. **按键采集用 GLFW 原始键盘事件**（mixin `KeyboardHandler.keyPress`）：精确 keydown/keyup + 修饰键掩码；vanilla KeyMapping 保留（控件菜单可见可改键），`keypress` 默认边沿维持现行为（保留 clicks 语义）；修饰键宽松匹配（必需键按下即可）；GUI 打开时不触发。
4. **硬切换**：无兼容层。缺 startup / 旧顶层行为字段 → 结构化"需迁移"错误 + 迁移文档；示例/文档/测试一次性重写。
5. **暂停功能舍弃**：任务只有 停止；状态仅 运行中/已停止。引擎无需任何冻结门控。
6. **历史**：内存环形 500 条，重启清空（与 logs/console ring 一致）。
7. **呈现**：活动栏"任务"图标 → 主区域整页视图（同设置/关于模式）；DevTools"任务"页签，与主视图共用 store+表格组件。
8. **行为配置收进 neomacro.yml 的 `config:` 块**（按类型子键），顶层仅身份字段；旧顶层行为字段报迁移错误。
9. **按键两层语义（补充澄清）**：`config.keypress.default-key` 是**建议值**；用户改键写入**独立 keymapping**（`CoreOptions.keybinds`，config.json 持久化，`""`=已解绑）——现有 `ScriptEntry.effectiveKey()` 已是"keymapping 覆盖 > 清单默认"结构，沿用并更名清单字段。

## Part 1 清单 `config:` 块 + startup 入口（core/engine）

**`core/module/manifest/MacroManifest.java` + `ManifestParser.java`**
- 顶层 `KNOWN_FIELDS` = `name/version/author/description/license/homepage/supportURL/main/permissions/config`。
- 新增 `config` 块（嵌套解析为 `MacroConfig` record）：
  - `config.keypress.{default-key, on, modifiers}`：**default-key = 建议初始绑定**（原版键名，如 `key.keyboard.j`，仅当 keymapping 中无该宏记录时生效）；on ∈ keydown|keyup|keypress（缺省 keypress）；modifiers ⊆ {ctrl,shift,alt} 小写归一。keypress 宏必须存在 `config.keypress` 块（内部字段可省用默认）。
  - `config.event.{on}`：String 或非空 List，load 时对 EventCatalog 校验（未知名报错并列出全部 34 个可用名）；event 宏必须声明。
  - `config.service.{lifecycle, autostart}`：可选，缺省用类别默认。
  - **绑定解析**：生效键 = `ScriptEntry.effectiveKey()`（keymapping 覆盖 > default-key）；用户改键（控件菜单、`/neomacros keypress bind|unbind`、面板中央绑定表）只写 `CoreOptions.keybinds`，永不回写清单。`MacroView.key` 继续暴露生效键（null=未绑定）。
- 旧顶层 `key/lifecycle/autostart/events/on/modifiers` → `ManifestParseException`，消息附迁移指引（如 `lifecycle → config.service.lifecycle`、`key → config.keypress.default-key`）。`permissions` 保留顶层（信任声明，非行为配置）。`dispose` 导出约定不变。

**`core/module/ModuleManager.java`**
- `KEY_HANDLER_EXPORT("onKey")` → `STARTUP_EXPORT("startup")`。load() 在 importModule 后 `readExportedFunction("startup")`，缺失 → ScriptError"必须导出 startup(...)，见迁移指南"。
- **event 自动订阅**：新增 `subscribeManifestEvents(module)`——对 `config.event.on` 每项 `bus().on(name, module.context().loop(), handler)`，handler = `session.invokeExport("startup", payload)`（payload 与 events.on 快照一致），`module.track(subscription)` 随卸载自动注销；ModuleManager 需访问 EventCatalog（构造注入或仿 `ScriptApiEnvironment` 静态访问）。
- `trigger()` 路由 startup（keypress payload：`{event: 边沿, key: 生效键, code, clicks, modifiers[]}`）。
- **`loadPhase` 改预过滤**：按 `manifest.lifecycleOr(category)` 在 load 前筛选，消除"全部加载后卸载不匹配者"的幻影任务/副作用。
- service：load 成功后调用一次 `startup()`（异步 Promise 经 AsyncPrimitives 在 context loop 落定，fire-and-forget 与现状一致，`GraalJsEngine.invokeExport` 无需改动）。

## Part 2 任务域（core）

- 新 `core/task/ScriptTask.java`：taskId（进程内 AtomicLong 自增）、macro、category、status(RUNNING/STOPPED)、startedAtMs、endedAtMs、triggerCount、startedBy(autostart/lifecycle/manual/web)、playerUuid/playerName、gameType(single/multi)、serverAddress("Integrated" 或 IP)、mcVersion。
- 新 `core/task/TaskRegistry.java`：active `ConcurrentHashMap` + history 有界 `ArrayDeque`(500) + `CopyOnWriteArrayList` 分发器，事件 `started/updated/ended` → 快照分发。元数据经 `core/task/TaskMetadataProvider` 函数接口由 product 在 bootstrap 注入（测试传 null → 字段留空）。
- `ModuleManager` 集成：`withTaskRegistry(...)`；load 成功 → start（taskId 存 `LoadedModule`）；unload → end(STOPPED)；trigger → triggerCount++。

## Part 3 输入层（product）

- 新 `adapter/mixin/KeyboardHookMixin.java`：inject TAIL `net.minecraft.client.KeyboardHandler#keyPress`；`mc.screen == null` 且 action ∈ {PRESS, RELEASE}（忽略 REPEAT）→ 取 GLFW 键码 + mods 掩码转发静态 hub；注册进 `neomacros.mixins.json`。
- 新 `adapter/KeyEdgeHub.java`：遍历 `modules.loaded()` 的 keypress 宏，按 `ScriptEntry.effectiveKey()`（keymapping 生效键）匹配（`InputConstants.getKey(...).getName()` 转换）、`config.keypress.on` 边沿过滤（仅 keydown/keyup 走此路径）、modifiers 子集匹配 → `modules.trigger(...)`。
- `adapter/FabricInputPort.java`：`keypress` 边沿维持 consumeClick；带 modifiers 时在 END_CLIENT_TICK 派发前用 `InputConstants.isKeyDown(window, …)` 轮询校验。
- bootstrap 注入 TaskMetadataProvider（`MainThread` 内取 `mc.isSingleplayer()`、`mc.getConnection().getServerData()`、player uuid/name、`mcVersion()`）。
