# 网络面板：≤1MB 内容预览/下载 + Chrome 风格详情标签页

## Context

当前详情面板只有"概览/Headers/Body"分组，响应体只能看 4KB 截断预览，无下载。本次两项升级：
1. **内容保留与下载**：请求体与响应体 ≤1MB 时在 mod 侧保留完整内容，编辑器按需拉取全量并支持下载文件（图片内联渲染）。
2. **详情 UI 重设计**（参考 Chrome DevTools 截图）：点击行展开的详情区改为标签页 —— **Headers / Payload / Response / Initiator / Timing**。

**已确认决策**：请求体与响应体同策略保留+可下载（共用预算）；图片类二进制内联渲染+全部二进制可下载；敏感头原样；Timing 需 mod 侧新增阶段数据；Initiator v1 用"宏名+入口脚本"（file:line 需引擎层包装调用栈，后续增量）。

## Mod 侧（neomacros）

### 1. `NetTraceEvent` 字段扩展（core/net/）

新增：`byte[] responseBody`（≤1MiB 保留的完整响应体，否则 null）、`String requestBody`（≤1MiB 保留的完整请求体，否则 null）、`Long waitMs`（发起到响应头到达）、`Long downloadMs`（响应头到落定）、`String initiatorFile`（发起宏的入口脚本路径，取 `LoadedModule.entry()`，null 同 initiator）。

### 2. `NetApi.fetch` 增强

- **Timing**：`sendAsync` 换自定义 `TimingBodyHandler`（包装 `BodyHandlers.ofByteArray()`，在 delegate 的 `onSubscribe` 触达时记 headers 纳秒时刻）→ `waitMs`/`downloadMs` 在 `whenComplete` 组装；失败且未收到头时两者为 null（总 `durationMs` 不变）。
- **保留**：`NetTrace.hasDispatchers()` 为真时才复制内容（web 关闭零开销不变）：请求体在入口处（String）超限置 null；响应体在 `whenComplete` 中 ≤1MiB（`1_048_576`）才挂到事件。常量 `RETAIN_LIMIT = 1MiB`。

### 3. `NetRing` 内容库（product/web/net/）

- 新增 `LinkedHashMap<Long, byte[]> respBodies` + `LinkedHashMap<Long, String> reqBodies`，总预算 `MAX_RETAINED = 32MiB`，超出时按 seq 从小到大逐出；ring 条目被逐出（超 500）时同步清对应 body。
- `append` 里事件带内容则入库并标记；DTO 新增布尔：`hasRequestBody` / `hasResponseBody`（即时入环与 SSE 广播只带布尔，不带内容本体）。
- 新增 `synchronized byte[]/String body(long seq, boolean requestSide)` 取内容（null=不存在或已逐出）。

### 4. DTO 与路由（product/web/v1/）

- `NetworkEntry` 增加 `hasRequestBody` / `hasResponseBody` / `waitMs` / `downloadMs` / `initiatorFile`。
- 新路由（形态仿 `/api/v1/pair-request/{id}`）：
  ```java
  @NmGet("/api/v1/network/{seq}/body")
  @NmApi(tag = "network", summary = "Fetch one retained request/response body")
  @NmError(status = 404, code = "not_found", ...)  @NmError(status = 410, code = "body_evicted", ...)
  public ApiV1 BodyResponse body(@NmParam("seq") Long seq, @NmParam("side") String side) // side 缺省 "response"
  ```
  成功返回原始字节 + 按条目 content-type 设 `Content-Type`（响应侧）；`Content-Disposition: attachment` 便于直接下载。404=seq 不在 ring；410=曾被保留但已被预算逐出或超限未保留。

### 5. 测试与 golden

- `CoreModuleExpansionsTest`：现有 net 记录用例扩展 —— 成功请求含 `waitMs/downloadMs`；响应体 ≤1MiB 时事件带完整字节（长度一致）；测试服务器加一个 >1MiB 上下文断言 `responseBody=null` 且预览仍 4KB；请求体保留断言。
- 新 `product/src/test/.../web/net/NetRingTest.java`：body 入库/预算逐出/ring 逐出联动/body(seq) 取回。
- `WebApiIntegrationTest`：新用例 —— 合成事件带 body → 回放条目 `hasResponseBody=true` → 签名 GET body 端点返回原始字节与 Content-Type；`side=request` 取请求体；未知 seq 404。消息用契约英文。
- Golden 重新提取（新路由 + 新字段；沿用失败报告 actual 侧提取法，命令见记忆）。

## Editor 侧（NeoMacros-editor）

### 1. 管线层

- `types/api.ts`：`NetworkEntry` 增加 5 个字段；`SseEventName` 不变。
- `client.ts`：`ApiResponse` 增加 `bytes: ArrayBuffer`——改为 `res.arrayBuffer()` 读原始字节，`text` 由 `TextDecoder` 解出（对现有 JSON 端点透明；二进制下载的前提）。
- `endpoints.ts`：`getNetworkBody(seq, side: 'request'|'response')`，404/410 抛 `ApiError` 原样（不静默降级，按钮处显式提示）。

### 2. `stores/network.ts`

`detailTab: 'headers'|'payload'|'response'|'initiator'|'timing'`（默认 `'headers'`，随过滤状态一起存活于组件重挂载）；清空视图时重置选中。

### 3. `NetworkTab.vue` 详情区重设计（本次主体）

详情头部：Chrome 式标签行（`Headers | Payload | Response | Initiator | Timing`）+ 关闭按钮。标签内容按截图：

- **Headers**：`General` 分组（Request URL / Request Method / Status Code 带色点（2xx 绿、3xx 黄、4xx/5xx 红、失败红 + 错误行）/ 开始时间 / 耗时 / 大小 / 发起者宏）→ `Response headers` 分组（kv 表 + `Raw` 复选框，Raw 态为 `name: value` 逐行纯文本）→ `Request headers` 分组（同上）。各分组标题可折叠（`▼`）。
- **Payload**：URL 查询参数表（解析 `new URL(url).searchParams`，无则略过）+ `请求体` 区（4KB 预览 + `查看完整内容`（hasRequestBody 时拉全量）+ `下载`）；均无 → "此请求没有载荷"。
- **Response**：文本类——4KB 预览 + `查看完整内容`（hasResponseBody 时 `getNetworkBody` 拉全量，`<pre>` 可滚动，超 200KB 先提示长度）+ `下载` 按钮；`image/*` 且 ≤1MB——内联 `<img>`（blob URL，关详情时 revoke）+ `下载`；其他二进制——大小 + `下载`；>1MB——预览 + "超过 1MB，未保留完整内容"；已被预算逐出（410）——提示"完整内容已被后续请求挤出缓存"。拉取态/错误态各自显示。
- **Initiator**：发起宏（resolveMacroId 完整 id）、入口脚本（`initiatorFile`，空显示 —）、说明行：无宏归属 = "DevTools REPL 或引擎外调用"。
- **Timing**：仿截图两段瀑布 —— `等待服务器响应`（waitMs，`--success` 色条）、`内容下载`（downloadMs，`--accent` 色条），条宽按占总耗时比例；失败（无阶段）显示单条红条 + 总耗时；底部合计行。阶段为 null 时显示 —。

**下载实现**：`downloadBlob(filename, blob)`（objectURL + `a[download]` + revoke，内联在 NetworkTab）；文件名取 URL 路径末段（去查询串），无则 `request-{seq}`/`response-{seq}`，按 content-type 补扩展名（json/txt/png/bin 最小映射）。

### 4. `dev-stub/server.mjs`

demo 增加：一条 ~300KB 文本响应体 + 一条小 PNG（真实 1×1 字节）+ 请求体带 body 的 POST；stub 侧 body 库（Map）+ `GET /api/v1/network/:seq/body?side=` 路由（读 query 免 NM1 的路径风格与现 stub 一致——签名校验保留）；404/410 分支可测。

### 5. 文档

`docs/mod-api-pending.md` §11 增补：新字段表、body 端点契约（404/410 语义、side 参数、Content-Disposition）。

## 假设与范围外

- 1MB = 1MiB（1048576 字节）；总保留预算 32MiB（按 seq 从旧到新逐出，UI 以 410 提示）。
- `Preview`（Chrome 的渲染预览标签）不单设标签——图片内联并入 Response；JSON 不会格式化树渲染（保持文本）。
- Initiator 的 file:line 调用点捕获需引擎层包装绑定（v1 不做，后续增量）。
- 请求头仍只记脚本显式设置的；Remote Address/Referrer Policy 类 General 字段 HttpClient 不暴露，不设。
